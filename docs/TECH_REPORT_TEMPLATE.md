# 1. 赛题理解与设计目标

## 1.1 比赛流程

【待补：用 3–5 句话说明两阶段流程】

参考写法：

- 第一阶段是独立采集赛，100 Tick、100ms/Tick，单车、无敌人、无随机事件，只允许 `move` / `wait`，按资源价值排种子。
- 两阶段之间有一个统一调整窗口。
- 第二阶段是 4 队同场对抗，500 Tick、500ms/Tick，包含资源、战斗、任务和自然语言随机事件。
- 第二阶段每场必须有本场、本席位的真实统一 AI 成功调用，否则任务分记 0。

## 1.2 计分规则（v1.1）

### 第一阶段

```text
第一阶段得分 = 40 × R1 / 200
```

- 普通资源价值 10，高价值资源价值 20。
- 全场资源总价值 200，满分 40。
- 第一阶段成绩只用于种子排位，不与第二阶段相加。

### 第二阶段

```text
资源得分 = 30 × min(R2 / 120, 1)
对抗得分 = 15 × min(D / 500, 1)
任务得分 = 5 × M
第二阶段总分 = 资源得分 + 对抗得分 + 任务得分
```

其中：

- `R2`：本队资源总价值。
- `D`：调整后的有效伤害。
- `M`：获计分资格的任务数。
- 资源最高 30 分，对抗最高 15 分，任务最高 15 分，总分最高 60 分。

### v1.1 有效伤害 `D` 的变化（重点）

```text
D(t) = max(0, D(t-1) + 本 Tick 实际攻击伤害 + 本 Tick 击杀奖励 - 60 × 本 Tick 死亡次数)
```

- `D` 可以为小数，可以下降，可以超过 500。
- 达到 500 时对抗项拿满 15 分；超过 500 的部分仍用于同分比较。
- 普通攻击、反伤、辣椒致死：每名被击毁车辆有 **60 点击杀奖励**，由致死批次中实际造成正伤害的合格贡献者按队伍去重后平分。
- 爆炸、世界分裂等环境死亡：**只扣 60 点死亡惩罚，不发击杀奖励**。
- 每次死亡扣 60 点有效伤害，最低为 0；世界分裂的立即复活也扣。
- 伤害任务使用调整后的 `D` 判断；任务完成后不因后续死亡扣除而撤销。
- 感知里的 `score.effective_damage` 已经是调整后的值，程序应直接使用，不要自己再加一次击杀奖励或死亡扣除。

> 【待补：确认你们的代码已按 500 门槛，而不是旧的 300。若还没改，在这里写“已完成 v1.1 适配”之前先改代码和测试。】

## 1.3 任务与 AI 约束

- 第二阶段三项任务内容**不固定**，以本场 `mission_text` 和 `missions` 为准。
- 任务类型可能包括：`normal_resources`、`high_resources`、`resource_value`、`effective_damage`、`reach`。
- 每个任务 ID 只计一次；完成后不因离开或阵亡撤销。
- 任务判定在战斗和死亡扣除之后，只为存活车辆检查。
- 每场必须有本场、本席位的真实统一 AI 成功调用，否则 `M=0`。
- 随机事件公告必须交给 LLM 理解，**不能用正则/关键词直接解析公告**。

## 1.4 设计目标

【待补：按你们实际目标写】

建议：

1. 通信稳定：不丢 Tick、不乱发动作、不写死席位和 token。
2. 第一阶段尽量高：稳定采集，目标 34+。
3. 第二阶段任务优先：先拿任务分，再收资源，再考虑打架。
4. 每场至少一次真实 LLM 成功调用。
5. 代码可维护、可回放、可测试，两个人能分别接手底层和策略。
6. 合规：只读公开话题，不读全图，不人工控制。

## 1.5 设计约束

- Ubuntu 22.04 + ROS 2 Humble + C++17。
- 所有话题 `std_msgs/msg/String`。
- 只能使用公开话题：`/team_X/perception`、`/team_X/action`、`/team_X/registration`、`/referee/mission`、`/referee/event_text`、`/referee/team_registry`。
- 不读取网页全图、测试配置、其他队感知。
- LLM 只走统一网关。
- 代码封存后不改源码、Prompt、决策参数；只按登记枚举切换 `decision_type`。

## 2.2 数据流

【待补：按实际代码描述，建议一段话 + 编号】

1. `BotNode` 订阅 `/team_X/perception`，把 `msg.data` 交给 `BotRuntime`。
2. `parse_perception` 把 JSON 转成 `Perception`：`tick`、`session_id`、自身状态、可见实体、任务、地图尺寸、事件文本。
3. `WorldMemory::update` 更新障碍、资源、已访问格、初始出生点、临时墙。
4. `Planner` 用 BFS 计算路径，避开已知墙、当前车辆、模型给出的危险区域。
5. `Stage1Policy` / `Stage2Policy` 把数据转成决策引擎的 `GameState`。
6. `DecisionEngine` 对候选动作评分，返回 `Decision`。
7. `BotRuntime` 做 `action_allowed` 检查，生成动作 JSON，由 `BotNode` 发布。
8. 下一帧从 `self.last_action` 读取执行回执。

# 3. 第一阶段：自主采集

## 3.1 规则与目标

- 100 Tick、100ms/Tick，共 10 秒。
- 单车、无敌人、无随机事件。
- 只允许 `move` / `wait`。
- 资源在机器人位于其格子时自动收集。
- 得分 = 40 × 资源价值 / 200。

## 3.2 地图与坐标

【待补：说明 9×9 相对坐标如何转绝对坐标】

参考写法：

- `self.position` 是本车绝对坐标。
- 每个实体的 `position` 是 9 行 × 9 列字符串，中心第 5 行第 5 列是 `1`，实体是 `2`。
- 相对位移 = `(2 的列号 - 5, 2 的行号 - 5)`。
- 绝对坐标 = `self.position + 相对位移`。
- 如果整张图没有 `2`，表示实体和自身同格，相对位移为 `[0,0]`。
- `0` 只表示占位，不代表可通行或在地图内。

## 3.3 地图记忆

【待补：按实际实现写】

- `Unknown` / `Free` / `Obstacle` 三种格子状态。
- 视野内看到的障碍标记为 `Obstacle`。
- 视野内没有障碍的格子标记为 `Free`。
- 自己走过的格子标记为 `visited`。
- 资源在视野内消失时，从记忆中删除。
- 阵亡时视野为空，不能用空列表清空地图。
- 临时墙到期后变回 `Unknown`，不能当成永久墙。

## 3.4 BFS 找路

【待补：说明 BFS 的输入、输出、障碍处理】

- 只允许上下左右移动。
- BFS 避开已知障碍、当前车辆、模型给出的危险区域。
- 找不到路时返回 `wait`，不崩溃。
- 移动失败不永久记墙；下一 Tick 用新感知重算。
- 有时序危险区时，可以“先等待，再通过”。

## 3.5 资源选择

【待补：按实际策略写】

参考写法：

- 优先选择“价值 / (距离 + 1)”较高的资源。
- 高价值资源 20，普通资源 10。
- 没有可见资源时，去最近的未知区域探索。
- 目标不可达时，换下一个目标。

## 3.6 异常处理

- 感知 JSON 解析失败：记录 warning，不崩溃，不提交臆测动作。
- 旧 Tick：丢弃。
- 同 Tick 重发：不重复推进，可复用缓存动作。
- 新场次：清空地图、缓存、LLM 结果。
- 移动失败：根据新感知重新规划。

# 4. 第二阶段：任务、资源与对抗

## 4.1 计分与优先级

【待补：结合 v1.1 写你们的实际策略】

建议：

1. 先做任务：`reach`、普通资源、高价值资源。
2. 资源做到 120 价值，拿满 30 分。
3. 有效伤害做到 500，拿满 15 分；打不过就跑。
4. 活着、少非法动作，同分时更有利。

> 注意：v1.1 的对抗满分门槛是 **500**，不是 300；击杀奖励 60，死亡扣 60。

## 4.2 任务处理

- 从 `missions` 读取结构化任务，不写死任务坐标。
- 任务内容不固定，以本场 `mission_text` 和 `missions` 为准。
- 每个任务 ID 只结算一次。
- 已完成任务不因死亡扣除而撤销。
- 伤害任务使用调整后的 `D`。
- 任务判定只为存活车辆执行。

## 4.3 资源策略

- 资源总价值 200，120 价值拿满资源分。
- 普通资源 10，高价值资源 20。
- 资源超过 120 后不再加资源分，但价值用于同分比较。
- 资源记忆只来自合法视野；资源消失要删除。

## 4.4 战斗策略

【待补：按实际决策引擎写】

参考写法：

- 普通攻击：同方向直线 1–2 格，命中最近敌人，20 HP。
- 防御：当 Tick 不移动、不攻击，普通受击 20→10。
- 出生保护：免疫攻击，不能 `attack`。
- 阵亡：只能 `wait`。
- 低血、敌人同轴、跑不掉时防御；否则拉开距离或继续任务。
- 攻击前看 `protected`，不打保护目标。
- 移动失败不增加 `invalid_actions`，但浪费 Tick。

### v1.1 有效伤害与击杀奖励

- 实际攻击伤害 + 击杀奖励 - 60 × 死亡次数，最低 0。
- 普通攻击、反伤、辣椒击杀：每名被击毁车辆 60 奖励，由合格贡献者按队伍去重平分。
- 爆炸、世界分裂：只扣 60，不发奖励。
- 同 Tick 多车互相击毁：各自先计伤害和奖励，再扣死亡惩罚。
- 策略评分要体现“击杀奖励 60”和“死亡扣 60”，不能只看单次 20 伤害。

## 4.5 随机事件

【待补：按实际 LLM 接入写】

- 事件公告只交给 LLM 理解，不用关键词/正则。
- LLM 输出结构化建议：危险区域、时间窗、目标、优先级。
- 本地校验坐标、时间、形状，再交给规划器。
- 爆炸：矩形 80 HP，无视防御，出生保护免疫。
- 世界分裂：十字线秒杀并立即复活，扣 60，不发击杀奖励。
- 辣椒：同 Tick 火线统一结算，击杀奖励 60 由合格触发者平分。
- 洁身自好：攻击防御目标会反伤；反伤致死时防御方参与分 60。
- 幻术：MOVE 方向反转，ATTACK 不反转；以 `self.position` 为准。
- 没有 LLM 回复时，不要自己用关键词解释公告；继续本地策略或保守行动。

## 4.6 决策模式

- `balanced`：任务 + 资源 + 顺路战斗。
- `collect`：保守收资源，尽量避战。
- `fight`：进攻型。
- 通过 `decision_config.json` 的 `decision_type` 选择。
- 每场最多申请 2 次切换；切换按裁判流程。

# 5. LLM 接入

## 5.1 定位

- LLM 只做高层建议：任务理解、事件理解、目标选择、战术建议。
- 不要求逐 Tick 生成动作。
- 底层动作由本地程序执行和校验。
- LLM 不能阻塞感知回调。

## 5.2 异步架构

【待补：按实际实现画图/描述】

```text
主线程（每 Tick）：
  收感知 → 更新地图 → 本地策略 → 发动作
       │
       └─ 只读“最新 LLM 计划”

后台线程：
  队列（最多 1 条待处理）
       ↓
  HTTP POST /v1/chat/completions
       ↓
  解析 JSON → 校验 → 写入 latest_plan
```

- 单在途请求，避免并发限制。
- 新请求覆盖旧待处理请求。
- 超时/失败保留旧计划或回退本地策略。
- 结果绑定 `session_id` 和请求时的 `tick`，过期丢弃。

## D. v1.1 计分速查

```text
第一阶段 = 40 × R1 / 200
资源 = 30 × min(R2 / 120, 1)
对抗 = 15 × min(D / 500, 1)
任务 = 5 × M
总分 = 资源 + 对抗 + 任务
D = max(0, 上 Tick D + 实际攻击 + 击杀奖励 - 60 × 死亡次数)
```

- 击杀奖励：每名被击毁车辆 60，普通攻击/反伤/辣椒；爆炸/世界分裂不发。
- 死亡扣 60，最低 0；世界分裂也扣。
- `D` 超过 500 仍用于同分比较。
- 任务内容不固定，以 `missions` 为准；已完成任务不撤销。
