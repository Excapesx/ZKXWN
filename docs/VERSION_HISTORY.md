## 如何看这些记录

1. 首先区分纯C++断言、模拟LLM、ROS替身、本地HTTP、真实DDS、官方裁判及真实模型。只有某一项通过不能自动推出其他项通过。
2. 旧版得分来自各自的模拟器、地图、对手和样本设计，不能跨报告直接排强弱。seat模式是分别对同阵容，duel才是同场；严格超过指定对手的比例不等于四人局冠军率。
3. 1.0固定f2f6eae，根目录旧程序后来可能继续演进；需要固定归档时用`versions/v1/01_程序源码/ZKXWN`。3.0和4.0保留仓库已有的队友修复。
4. 2.0存在跨场资格与线程问题；5.0的原实验未胜过4.0；8.0的7项独立反例见它的检验补充；9.0修复这些问题，同时在一组混合对手中少拿约0.38分。没有通用“秒杀”结论。
5. 9.0拒绝无场次话题作为新场决策事实，晚加入或重启可能缺少已滚出感知窗口的历史。仍需Ubuntu和官方裁判验证，不能用观赛全图或隐藏真值补齐。

## 当前运行入口

```bash
cd ~/ZKXWN/versions/v9
bash ./scripts/test.sh
bash ./scripts/build.sh
bash ./scripts/run.sh A 2
```

依次进入9.0、执行本地检查、编译ROS节点、启动A席位第二阶段。需要先具备Ubuntu/Humble环境；裁判、公开ROS域和真实网关按官方要求另行准备。

各历史版README给出本版命令。不要把v5的目录名误认成rmtc_bot5：它仍叫rmtc_bot3；v3/v4都叫rmtc_bot2。
