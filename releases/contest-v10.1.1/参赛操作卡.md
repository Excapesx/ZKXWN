# HERO 10.1.1 参赛操作卡

当前正式组合：本机10.1策略（2000伤害阈值）+官方网关接入修复+512输出限制，默认balanced。规则PDF为v1.2；本机公开练习二进制仍为v1.1

## 赛前完成

```bash
cd ~/ZKXWN/releases/contest-v10.1.1
python3 scripts/verify_delivery.py
bash scripts/doctor.sh
bash scripts/build.sh
```

完整开发版也可从versions/v10.1.1执行相同命令，两者选定一个实际运行目录。提前编译，不在3分钟部署窗口里安装依赖或寻找其他工作区

## 每场启动

```bash
bash scripts/contest.sh
```

1. 输入赛事当天对应赛场公布的ROS域号，不猜测正式域号
2. 输入本场A/B/C/D席位；第一阶段单车使用A
3. 输入阶段1或2。第二阶段输入本场官方网关和本场席位令牌，令牌隐藏且不写文件
4. 核对HERO-10.1.1、席位、阶段、max_tokens=512和实际二进制路径
5. 确认本席位感知→同tick/session动作→下一感知self.last_action执行回执
6. 第二阶段确认官方记录本场本席位真实AI成功，随后对新公告实际调用LLM理解。Ready和练习mock均不能代替

默认关闭思考、JSON输出、非流式。模型由官方网关统一为deepseek-flash，清空RMTC_MODEL。按公告变化调用，计划预算90次，成功上限100次按令牌生命周期累计

换场、换席位或换令牌时Ctrl+C后重新运行脚本。reset_session不会更换进程内的旧令牌。只停止自己的程序，不操作裁判服务

## 策略和窗口

根目录decision_config.json默认只有decision_type=balanced。balanced/collect/fight赛前登记后，按最新群通知只在轮间10分钟窗口改这个枚举，并按流程重启。collect的战斗系数0.7、追猎半径5；balanced为1.0、10；fight为1.4、10。本次推荐balanced，未验证另两种更强

不在单场临时改源码、Prompt、坐标或其他参数。地图公示不意味着可以把全图写入配置。上场前配合检查Git状态、实际运行路径和封存版本

## 验证边界

完整包回归见验证报告。独立组合候选已跑正式动作周期的练习两阶段、非法动作0。这使用本机v1.1裁判和mock AI，真实LLM、正式资格、现场网络和完整v1.2仍需联调

文件清单严格核对源码。仅根目录decision_config.json允许按已登记枚举改变decision_type，检查工具会报告配置是否变化；它不会替你取得现场切换许可。新增键或未登记枚举仍拒绝启动
