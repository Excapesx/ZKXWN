# HERO 10.4.1 比赛操作卡

这份操作卡用于 Ubuntu 22.04 + ROS 2 Humble。先在自己的参赛电脑完成一次构建和启动演练。Windows不能直接运行这些命令。第一阶段不调用LLM；第二阶段使用官方统一网关，真实调用与资格必须在现场核验。

## 1. 进入程序并构建（赛前做）

下面假设仓库在主目录ZKXWN；实际目录不同时只替换cd后面的路径。

```bash
cd ~/ZKXWN/releases/contest-v10.4.1
python3 scripts/verify_delivery.py
bash scripts/doctor.sh
bash scripts/build.sh
```

`cd`切换目录；`python3`运行交付校验，ok=true说明列出的文件摘要一致，不代表已通过实机验收；`doctor.sh`检查工具和依赖；`build.sh`加载系统ROS并把源码编译成可运行节点。需要C++17、CMake、colcon、rclcpp、std_msgs及libcurl开发依赖。本包不自动安装系统软件。

从桌面ZIP传入Ubuntu的，进入解压后参赛包的实际目录再执行同样的后三行。不要同时运行完整包和精简包。

## 2. 当场启动（推荐）

```bash
bash scripts/contest.sh
```

按提示依次输入官方域号、席位、阶段；第二阶段再输入官方网关和本场令牌。令牌输入时屏幕没有字符是正常的，输入后回车。配置只留在本次进程中，不写配置文件。程序自动拼接Authorization: Bearer请求头，POST到/v1/chat/completions；关闭思考、请求JSON输出、max_tokens=1024，不自行指定模型。

看到HERO 10.4.1和Ready后先核对席位、阶段；第二阶段还应出现LLM已启用。Ready只说明程序已启动，LLM已启用也不等于真实调用成功或任务资格成立。等待裁判开始时可能暂时没有新输出，不要重复启动第二个节点。

## 3. 检查接入（另开终端）

```bash
source /opt/ros/humble/setup.bash
read -r -p '输入刚才相同的官方域号: ' ROS_DOMAIN_ID
export ROS_DOMAIN_ID ROS_LOCALHOST_ONLY=0 RMW_IMPLEMENTATION=rmw_fastrtps_cpp
read -r -p '输入本场席位A/B/C/D: ' SEAT
ros2 topic list
timeout 10 ros2 topic echo "/team_${SEAT}/perception" std_msgs/msg/String --once
timeout 10 ros2 topic echo "/team_${SEAT}/action" std_msgs/msg/String --once
```

`source`把ROS工具加入当前终端；`export`让工具使用同一通信域；`${SEAT}`会替换成输入的席位；`--once`收到一条就退出；`timeout 10`最多等10秒。看到话题名仅证明发现话题，看到action也不等于裁判接受。裁判运行后检查公开感知中的last_action/回执与当前场次Tick，现场让裁判确认接入及真实LLM资格。暂停、尚未注册、域号不一致和网络未通都可能无输出，不能仅凭超时判定原因。不要读取观赛全图或内部消息作为决策输入。

## 4. 停止、换阶段和换场

在启动程序的终端按Ctrl+C，等待命令提示符返回。换阶段或更换令牌，重新运行contest.sh并填本场信息。不要在仍运行的节点终端里继续粘贴另一条启动命令。不要用killall停止裁判或队友程序。

## 5. 保存测试证据（练习时用，比赛时按官方要求）

在已设置域号和席位的诊断终端执行：

```bash
mkdir -p ~/rmtc_evidence
ros2 bag record -o "${HOME}/rmtc_evidence/match_$(date +%Y%m%d_%H%M%S)" "/team_${SEAT}/perception" "/team_${SEAT}/action" "/team_${SEAT}/registration" /referee/event_text /referee/mission
```

`mkdir -p`创建证据目录；`ros2 bag record`录制本队公开通信，日期用于避免覆盖旧录制。结束按Ctrl+C等待写盘；随后可用`ros2 bag info 实际录制目录`查看数量。录制不代表对局正确，仍需审计回执。

## 6. 常见情况

- No token/LLM未启用：停止节点，再用contest.sh填写第二阶段本场令牌和网关，不能拿练习令牌当正式令牌。
- 401：检查令牌是否对应本场本席位，联系裁判确认；不要反复刷请求。
- 配额耗尽或并发限制：按官方限制处理，不能通过多开节点规避。当前单工作线程及重试实现仍需真实网关确认，未宣称已满足未知配额。
- 运行的是旧版本：新终端进入本包，重新build.sh再contest.sh；启动指纹中的路径应属于本包。
- 缺依赖、无感知、失败回执：保留完整错误和场次号，先请队友或裁判确认，不临场随意修改封存代码。

本操作卡与新启动脚本尚未在真实Ubuntu/ROS/官方网关完整演练。正式比赛前须由两人各自执行一次，未知字段由官方通知填写。完整开发包仍保存模拟工具、历史基线和测试；精简包只提供参赛构建运行及核验材料。
