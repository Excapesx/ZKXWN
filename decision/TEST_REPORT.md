## 验证中修正的问题

初次 37 个场景中有 1 个失败：预计本回合必死时，移动后的较低风险仍被计入收益。已修正为：预计在攻击阶段死亡时，不计后续移动、采集和到点收益，也不计算其下一回合站位；同 Tick 普通攻击仍可结算。修正后加入任务、易伤与退场场次迟到消息案例，最终 41 个通过。

Windows 已安装的 Dev-C++ 自带 GCC 4.9.2，CMake 探测表明其不支持本项目要求的 C++17，未使用它构建，也未修改或升级该软件；改用已安装 MSVC 完成验证。

## 结果的限制

尚未在 Ubuntu 上编译本模块，不能把此前 Ubuntu 环境验证当作本模块已通过 Linux 构建。源码使用标准 C++17，CMake 可供后续 Ubuntu G++ 11 构建，但其实际结果仍需记录。

本轮未进行真实 ROS 发布订阅、底座适配、LLM 网络调用、完整 100/500 Tick 比赛、策略成绩比较、现场跨机器网络或镜像验证。用例都是人工构造的局部场景，不能证明对真实对手必胜或全面处理事件。完整说明见 README 与接口草案。
