# 校内9.0的程序怎样运行

## 一帧数据从哪里进来

ROS节点订阅本席位的感知话题。收到JSON后，先检查数据是否合法、是不是当前席位、Tick有没有重复或倒退，以及场次是否发生变化。

重复Tick只重发缓存动作，避免同一帧推进两次记忆。换场次会重置地图、计划、模型调用状态和公告记录；已经退场的旧session感知不能再产生旧动作。

相关代码：`ros2_ws/src/rmtc_bot9/src/node.cpp`、`src/rmtc9/frame_gate.hpp`、`src/rmtc9/parse.cpp`。

## 第一阶段

程序从合法视野记住障碍、空地和资源，把已知资源与有信息价值的观察点一起规划。先保证已知资源的收集，再用剩余时间探图。它知道规则公布的资源总量，但不知道没看见的资源实际坐标。

路径会随着新障碍和资源变化重算。第一阶段只发送MOVE或WAIT，不调用模型理解随机事件。

## 第二阶段

每一帧先处理已经知道的事件和历史，再比较当前可做的事情：

1. 当前Tick的前置事件是否已经足以致死；如果是，不能假装靠稍后移动逃掉。
2. 下一Tick附近是否有危险，当前能不能先离开。
3. 脚下资源、攻击、采集、任务点、回血或堡垒等机会值多少。
4. 追击和巡逻有没有意义，目标路线是否仍能走。
5. 比较攻击、防御、移动的估计收益，输出本Tick的一个动作。

这些收益包含启发式和对手动作假设，不是对未来局势的精确证明。只看得见的敌人及合法历史参与推断，程序不会读取观赛全图或离线裁判真值。

## 攻击怎样估计

`battle.cpp`分别估计对手保持、朝自己攻击、选择机会目标等情景。每个对手在一个情景里只做一个动作；不能同时假设它攻击两个目标。伤害贡献、多人击杀分配、死亡扣除及伤害任务的存活门槛都会影响估值。

9.0允许从公开历史学习对手习惯，但“我没掉血”并不能说明对手没开枪。例如中间有一辆车挡枪，就不能积累被动证据。最坏攻击情景也会保留。这会减少一部分冒险收益，具体得分变化看本次报告。

## 事件和LLM怎样配合

模型线程异步接收当前场次公告，返回结构化事件。主决策不会停下来等模型。模型回答还要经过本地字段、坐标、时间及事件身份检查，之后才能影响危险场和目标选择。

本地不会靠自然语言关键词或正则替代模型解释公告。离线模拟中的oracle和查表假网关只用于开发测试，不参与正式节点的决策输入。

同一个事件ID只能代表一个事实。时间寻路如果判断先等几Tick才能过墙，会把“第一步等待”传回决策，不能把未来可通行误当成现在可走。

## 先学会哪几件事

建议每次只跟一条链：看一帧感知里的位置、血量、Tick和session；找到程序选择的动作及reason；再对照下一帧回执，确认有没有移动、有没有掉血。

例如`wait_for_window`表示路线还有价值，但现在先停留。第二阶段可以用DEFEND停留，WAIT首动作表示“不移动”，不表示必须发送WAIT枚举。`defend_threat`表示当前攻击风险使防御更合适。`pre_event_forced_death`表示已知前置事件先于本Tick动作结算，当前移动无法逃避。

先读懂这几种输出，再修改一个输入观察变化，会比一次照抄整套命令更容易理解。这个包的自动测试只证明指定场景的程序行为，不证明你已经独立掌握了相应知识。
