# 程序逻辑与学习指南（8.0）

这份指南按“一帧感知怎样变成一个动作”的顺序讲。7.0 已有的部分简单带过，8.0 新增的部分讲原理。比赛有代码审查和个人答辩，建议每一节都对着源码读一遍，能用自己的话讲出来再上场。

## 一帧消息怎样变成动作

1. **收感知**（`ros2_ws/src/rmtc_bot8/src/node.cpp` 的 `on_perception`）。ROS 节点收到 `/team_X/perception` 的 JSON，交给 `parse_perception`（`src/rmtc8/parse.cpp`）做容忍式解析。关键字段缺了才丢帧，这些字段是 tick、session_id、地图尺寸、self.position；单条坏实体只跳过这一条。
2. **过帧门**（`frame_gate.hpp`）。同一 Tick 重发就重发缓存动作，不重复推进策略；旧场次的迟到帧丢掉；新场次清空所有记忆。
3. **整理公告、按需问模型**（`maybe_request_llm`）。见下面“模型在这里做什么”。
4. **决策**（`src/rmtc8/bot.cpp` 的 `Bot::decide`）。先 `prepare` 更新地图记忆、事件危险场、敌人目击、“不开火对手”计数、距离场，再按阶段进 `stage1` 或 `stage2`。
5. **出口守卫**（`sanitize_action`）。阵亡只能 WAIT；出生保护期不攻击；第一阶段只能 MOVE/WAIT；方向必须合法。然后连同原样的 tick、session_id 发到 `/team_X/action`。

## 第一阶段：边探图边规划路线（8.0 新）

7.0 的做法：看得见资源就按最短路线吃完，看不见了才去最近的未知区域。毛病是不会“顺路多看一眼”：经常在出生点附近来回吃，等想起去另一半地图，时间已经不够了。

8.0 的做法（`Bot::stage1_view_tour`）：

1. **还有几个没露面？** 规则公布了每场 16 个资源（12 普通、4 高价值）。用“总数 − 看见过的 − 已收集的”就知道还有几个藏着。全部露面后，直接用 7.0 的最短路线。
2. **选观察点。** 观察点就是“站过去就能看到一大片未知格”的位置。用贪心集合覆盖：每次挑一个能新看到最多未知格的点，把这些格记为“已覆盖”，再挑下一个，最多 4 个。
3. **给观察点估价。** 价值 = 每个未知格平均藏着的资源价值 × 能看到的未知格数 × 0.6（打折，因为看到后还要绕路去捡）。另外给它加一段“路程垫”：预计露面几个资源，就多算 3×几 个 Tick。
4. **统一排路线。** 已知资源和观察点一起交给定向越野求解器（`solve_tour`）。它会在剩余 Tick 内找“总价值最大、同价值时最短”的访问顺序，13 个点以内是精确动态规划，状态是“已访问集合 × 当前所在点”。已知资源的权重是观察点的 1000 倍，所以路线一定先保证吃下已知资源，探图只用富余时间。
5. **防摆动。** 观察点每走一步都会变（新格子被看见了），容易在两格之间来回走。两条规则：上一 Tick 追的观察点只要还有足够新格子就留着；“坚持原目标”的路线如果价值一样、只长 2 Tick 以内，就坚持。

在视野 2 或 24×24 这种非标准尺度上，观察点的估价不可靠，程序会自动退回 7.0 的路线。

## 第二阶段：候选目标打分

7.0 的框架没变：把“去哪个格子”都变成候选目标，每个目标有一个“比分收益 ÷ (距离+1)”的分数，取最高的走一步；能开火时把攻击价值和最好目标比；致命时考虑防御。8.0 在里面加了四件事。

### 1. 开局路线（`Bot::stage2_route_goal`）

前 80 Tick 用和第一阶段一样的“观察点 + 资源”路线，有两点不同：
- 已知资源会被抢。如果视野里有敌人比我先到，这个资源打 2 折；如果我先到、敌人紧随其后，乘 1.65 鼓励去抢。这是 7.0 原有的规则。
- “还有几个没露面”要随时间打折，因为别人也在采。

这个目标有三条禁区，下面任何一种情况都不出路线目标，因为探图的期望价值是粗估，不能压过这些更要紧的事：能开火时、血量低于 50 时、有天使/堡垒/辣椒事件时。

### 2. 追猎与巡逻

资源一般在第 50 Tick 前就被采光，后面 450 Tick 主要靠打架拿对抗分（D 到 500 封顶）。7.0 的追猎半径只有 5 格，后期大部分时间在漫游。8.0：
- 追猎半径 10，即整个 9×9 视野内的敌人都算。
- 看不见敌人时巡逻：任务点、地图中心、四个象限中心，加上复活点。复活点有两个来源：一是看到某个敌人处于出生保护，它就站在自己的复活点上，记下来；二是按自己出生点在地图上的位置，镜像猜另外三个角。一个巡逻点去过后 40 Tick 内不再去。
- D ≥ 500 后不再主动追（再打对抗分也不涨）；D ≥ 560 后连目击搜索也停。多留 60 是因为再死一次会扣 60。

### 3. 识别不开火的对手（`Bot::is_passive`）

`incoming_damage` 估计“这 Tick 我最多挨多少打”：凡是和我同行或同列、相距 1–2 格、中间没挡着的敌人，都算会开火。这是保守的上界。碰到只打相邻目标的程序，这个上界一直是错的：7.0 在 20 血时认定必死，就一直防御。

8.0 的修法很简单：每个 Tick 记下“哪些敌人和我对齐了”；下一 Tick 如果我的血没掉，这些敌人各记一次“没开火”，掉了血就清零；连续 3 次没开火的敌人，不再算进来火，战斗预估里也不让它开火。这只用了自己的血量变化，都是合法信息。

### 4. 战斗估值（7.0 原有）

`attack_action_value` 用三种情景估计攻击收益：敌人不动、敌人全打我、敌人各找机会。每个敌人在一个情景里只选一个动作，伤害同时结算，击杀奖励 60 按贡献者均分，死亡扣 60。把三种情景加权平均，换算成对抗分的增量（15×D/500）。

## 模型在这里做什么

规则要求随机事件必须交给大语言模型理解，不能用正则或关键词去解析公告。程序可以校验模型的输出。

1. **攒公告**（`src/rmtc8/announce.hpp` 的 `AnnouncementLog`）。感知里的 `event_text` 是“近期公告”的滚动窗口，话题 `/referee/event_text` 是一条一条发。8.0 把两边收到的每一行都存起来，完全相同的文本只存一次。这里只做“文本行去重”，不看内容。
2. **决定什么时候问**（`PlanScheduler`）。有新公告行才问。两次之间至少隔 max(3, 剩余 Tick ÷ 剩余预算) 个 Tick，保证整场不把 100 次配额用光。
3. **问什么。** 把最近 48 行公告、当前 Tick、地图尺寸、自己位置发给模型，要求只回一个 `{"events":[...]}`，每种事件的字段含义都写在提示词里。
4. **收结果**（`drain_llm`）。只要 HTTP 2xx 就记“本场已有 AI 资格”，任务分要靠这个。结果只要不比已用的计划旧就采用。
5. **校验**（`parse_plan`）。逐条检查，坏的一条只丢这一条。缺的数值用规则正文公布的标准值补，例如爆炸 80。模型用规则原文名字（比如 pepper）也认。
6. **用起来**（`events.cpp` 与 `bot.cpp`）：
   - 爆炸、世界分裂变成“某 Tick 某格危险/是墙”，距离场改用时间展开 BFS，到达该格时墙还在才绕开。
   - 天使、堡垒、辣椒变成目标。
   - 幻术让移动方向反过来。
   - 易伤、反伤进入战斗估值。

模型调用全在后台线程（`llm.cpp`），决策主循环从不等它。超时 15 秒，读超时不重试，因为网关可能已经成功并扣了配额。

## 测评工具怎么用、怎么读

- `tools/bench/referee.cpp` 是离线裁判，按规则 PDF §5.2 的顺序结算，含 8 种事件。它不是官方裁判，只用来比较版本。
- `./scripts/bench.sh` 的 seat 模式：同一张图、同一个席位、其余三席完全相同，先放 8.0 打一局，再放 7.0 打一局，比较这个席位的得分。
- 输出里要看这几项：`mean_difference`（平均分差）、`map_bootstrap_95`（95% 区间，不含 0 才算显著）、`damage_capped`（伤害满线率）、`mission_high` 等（各任务完成率）。
- `tools/node_sim/` 把真正的节点代码接到离线裁判和本地假网关上，用来检查协议格式与模型链路，不需要 ROS。

## 从哪些文件读起

| 文件 | 先理解的问题 |
| --- | --- |
| `src/rmtc8/types.hpp` | 一帧感知里允许知道哪些东西？动作、事件、计划怎么表示？`Config` 里的资源总数是干什么用的？ |
| `src/rmtc8/bot.cpp` 顶部常量 | 每个参数控制什么？为什么不能做成可现场修改？ |
| `src/rmtc8/bot.cpp` `stage1` / `stage1_view_tour` | 观察点怎么选？为什么已知资源权重要大很多？摆动是怎么来的、怎么防？ |
| `src/rmtc8/bot.cpp` `stage2` | 每类候选目标的分数怎么算？攻击、防御、移动最后怎么比？ |
| `src/rmtc8/grid.cpp` `solve_tour` | 定向越野的动态规划状态是什么？复杂度多大？ |
| `src/rmtc8/parse.cpp` `parse_plan` | 哪些情况整份拒收，哪些只丢一条？为什么缺值可以用规则标准值补？ |
| `src/rmtc8/announce.hpp` | 为什么只做“行去重”不算关键词解析？节流间隔怎么算？ |
| `ros2_ws/src/rmtc_bot8/src/node.cpp` | 感知、公告、模型结果、动作发布怎样接起来？AI 资格什么时候记？ |

## 答辩时容易被问到的

1. **“为什么不直接用关键词解析公告，更快更稳？”** 规则 §8.1 明确禁止用正则、关键词、固定句式替代模型判断。程序只能校验模型输出。`AnnouncementLog` 只按整行文本去重，`canonical_kind` 只归一模型输出的字段名，两者都不读公告的含义。
2. **“资源总数 16 是不是用了隐藏信息？”** 不是。规则 §4.2 公开了每场资源数量和总价值，赛前如有调整也会统一公布。
3. **“镜像猜复活点是不是越权？”** 只用了本车自己的出生点和地图尺寸，属于“根据合法信息预测对手”（§13 明确允许）。猜错了也只是巡逻白走一趟。
4. **“决策参数为什么写死？”** 规则 §2.3：现场只能改 `decision_type`，不能改其他决策参数。
5. **“离线测评赢了，正式比赛一定赢吗？”** 不一定，看性能验证报告的“不能据此得出的结论”一节。

## 命令拆解

- `./scripts/test.sh`：编译并跑六组测试。通过只说明这些用例通过，不能说明已连通裁判。
- `./scripts/build.sh`：加载 ROS 2 Humble 环境，用 colcon 编译 `rmtc_bot8`。只能在装好 ROS 的 Ubuntu 上用。
- `export ROS_DOMAIN_ID=27`：设置当前终端的 ROS 通信域，27 是公开练习用的；正式比赛用主办方公布的值。
- `./scripts/run.sh A 2`：以 A 席位启动第二阶段节点。第一阶段把 2 换成 1；其他席位换成 B、C、D。
- `./scripts/bench.sh ...`：离线比较 8.0 和 7.0，不连 ROS，不访问模型，也不是官方比赛。
- `./scripts/node_sim.sh ...`：不装 ROS 跑一整场真实节点和本地假网关，用来检查协议格式和模型链路。
