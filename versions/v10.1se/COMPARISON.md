# v10.1.1 vs v10.1se：24×24 随机事件/任务对比

## 方法

- 地图：24×24，约 13% 随机墙，四角出生，16 个资源（12 普通 ×10 + 4 高价值 ×20）。
- 任务：标准三项（2 普通、1 高价值、中心 reach）。
- 事件：8 种标准事件，按 `standard` 参数随机生成，公告/生效 Tick 随机。
- 对局：500 Tick，4 个机器人，64 张地图 × 4 席位 = 256 局。
- 事件计划：使用离线 oracle 在公告后交付结构化 plan，避免把真实 LLM 质量混入策略对比。
- 比较对象：`v10.1.1` 与 `v10.1se` 各自独立编译、独立运行；地图/种子完全相同。

> 这不是官方裁判/官方地图成绩，也不能替代真实统一 AI 资格。
>
> 这里的 38.05 是“四个同版本机器人 + 24×24 + 标准事件”的对照分，不是之前 41.18（对三个 9.1）的同一实验，不能跨实验直接比较。

## 正常场景：结构化任务存在

| 指标（A 席） | v10.1.1 | v10.1se |
|---|---:|---:|
| 平均分 | **38.0469** | **38.0469** |
| 资源 | 43.438 | 43.438 |
| 有效伤害 | 1017.79 | 1017.79 |
| 任务 | 2.438 | 2.438 |
| 死亡 | 9.703 | 9.703 |
| 非法动作 | 0 | 0 |

**256 条逐局结果完全一致。**  
原因是正常比赛一直提供结构化 `missions`，`v10.1se` 的 LLM 任务兜底不会启用。

结论：**正常场景没有涨分，也没有回归。**

## 退化场景：A 席结构化任务缺失

为了验证兜底，单独把 A 席感知中的 `missions` 清空，裁判仍按真实三项任务计分：

| 指标（A 席） | v10.1.1 | v10.1se |
|---|---:|---:|
| 平均分 | 37.2656 | **38.0469** |
| 资源 | 43.750 | 43.438 |
| 有效伤害 | 998.61 | 1017.79 |
| 任务 | 2.266 | **2.438** |
| 死亡 | 10.172 | 9.703 |
| 非法动作 | 0 | 0 |

A 席配对差值：

```text
平均 +0.7812 分
标准差 5.0567
bootstrap 95% 区间 [-0.4297, +2.0312]
胜/负/平：22 / 11 / 31
```

解释：

- `v10.1se` 把任务完成数从 2.266 拉回 2.438，约 +0.86 分任务分；
- 但资源略低、伤害略高，最终净 +0.78；
- 区间跨零，**不能证明稳定提升**；
- 这是**最好情况**：兜底目标直接用了官方 `map.missions`（含匹配 ID），不是真实 LLM 从文本解析出来的。

## 结论

1. **正常比赛场景：v10.1se 与 v10.1.1 完全一致**，没有回归，也没有额外收益。
2. **结构化任务缺失时：v10.1se 能恢复一部分任务分**，本实验平均 +0.78，但统计上不显著。
3. **真实 LLM 质量未测**：本实验用 oracle 事件计划和直接注入的任务兜底，真实模型可能解析错、漏目标或幻觉坐标。
4. 因此 `v10.1se` 应定位为**鲁棒性候选**，不是涨分版本；正式比赛仍应优先 `v10.1.1`，除非现场出现结构化任务缺失/任务文本变化。

## 复现

```bash
# v10.1se 自带 se_compare 目标
cd versions/v10.1se
cmake -S . -B build/tests -DCMAKE_BUILD_TYPE=Release
cmake --build build/tests --target se_compare -j4
./build/tests/se_compare 64 20261030 normal   > normal_v101se.jsonl
./build/tests/se_compare 64 20261030 fallback > fallback_v101se.jsonl
```

`v10.1.1` 侧使用同一个 `tests/se_compare.cpp`，在临时副本中编译运行，不改正式包；原始逐局结果已保存在 `evidence/se_compare/`。

原始逐局 JSONL 和汇总在 `evidence/se_compare/`。
