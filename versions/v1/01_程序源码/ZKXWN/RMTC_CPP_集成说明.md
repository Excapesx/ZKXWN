## 2. 核对后修正的要求

- 官方消息的字段叫 `self.protected`，不是 `self.is_protected`。后者只用于 C++ 成员名。
- 任务类型是 `normal_resources` 和 `high_resources`，按公开协议映射。
- 通过启动配置明确阶段，不根据 `missions` 是否为空推断。
- 移动失败可能是占用或结算变化，不直接永久标墙；以新感知的位置和实体重算路线。
- 原决策模块已经映射幻术下的 MOVE 方向，底座不能反转第二次，ATTACK 不反转。
- 事件公告只能交模型理解；本地程序校验模型结构，不用公告关键词做隐形解析后备。
- 已解析的区域和效果按绝对 Tick 保留，死亡不清除；过期和旧场次结果不得继续生效。

## 5. 建议你先学的一小段

先只读 `decision/src/engine.cpp` 中的阵亡分支：

```cpp
if (!s.self.alive || s.self.hp <= 0) {
    result.reason = "dead_wait";
    return save(result, "");
}
```

自然语言：如果车没有存活，或者血量已经为零，就把本 Tick 的等待结果保存下来并立刻返回。

- `if (...)` 是条件判断。
- `!` 表示“不是”；`||` 表示“或者”；`<=` 表示“小于或等于”。
- `s.self.alive` 是当前状态里本车的存活字段，点号表示逐层取成员。
- `result.reason = ...` 是给解释字段赋值，不会发送 ROS 消息。
- `return` 结束这个函数；`save` 是保存本 Tick 结果的辅助函数。
- `result` 的默认动作是等待；后面 Runtime 才把它转成 JSON 并交给 ROS 发布。

你可以用假感知把 `alive` 改成 false、`hp` 改成 0，观察回放动作从 move 变成 wait，然后用自己的话说明原因。先做到这一步，再读资源目标和风险评分。
