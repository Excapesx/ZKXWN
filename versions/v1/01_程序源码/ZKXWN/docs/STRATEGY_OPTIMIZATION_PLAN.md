## 2. 正式规则明确了什么

- §10.2：`D_next=max(0,D+本Tick实际攻击贡献+全部击杀奖励-60×本Tick死亡次数)`；D可为小数、可下降、可超过500。得分为 `15×min(D/500,1)`，超过500仍参与同分比较。
- 击杀每辆总池60，致死批次中造成实际正伤害的队伍去重平分；此前Tick攻击者不分。不是固定三分之一，也不能简单独占。过量名义伤害按剩余HP比例分配实际贡献；普通攻击、反伤可能共同分摊。
- 反伤和辣椒损血不算普通攻击贡献，但合格贡献者可分击杀奖励；爆炸、分裂死亡无击杀奖。战斗阶段已死目标不得再算辣椒击杀。
- §5.2：前置事件→事件死亡/分裂复活强制等待→防御→同时战斗及击杀→死亡→存活者移动→辣椒等入点事件→存活者堡垒/回血→扣死亡额度→存活者资源/任务检查。
- 伤害任务使用调整后的D，只对任务检查时存活者判定；完成ID之后保留。必须把攻击对抗收益与存活任务收益分开。
- defending仅是最近状态，不保证敌人下个动作。敌人离开视野即失去实时真值；没有公开敌方总分输入，不能假装知道本队实时排名。
- 任务与资源不存在固定的第二阶段先后时间段；可按自己可见的机会同时比较，不能把第二阶段前若干Tick硬当作官方“资源阶段”。
- 正式任务资格来自本场本席位真实统一AI成功记录。HTTP成功、本地解析成功与裁判确认应分别记录；练习/模拟成功不能冒充正式资格。

| 位置 | 现状 | 优化理由 |

## 4. 建议实现顺序

### P0：先使收益与结算一致

在`decision/`新增标准C++的结算预测组件（暂名`battle_evaluator`），与底座combat辅助协作；只预测候选，不改裁判历史状态。

输入包括公开车辆与HP、候选动作、已校验模型事件解释、信息时效/来源。输出分开保存：实际伤害预测、贡献者集合、击杀份额、死亡次数、结算后D/HP/存活、可完成任务与不确定项。

针对普通战斗先实现：方向与最近目标、保护挡枪、同时伤害、防御20/10、可见多人火力过量分摊、击杀去重、先奖后罚。事件扩展沿同一时序接入。

评分使用 `Δ资源分 + Δ对抗分 + 可结算任务收益 - 后续机会损失 - 不确定性风险`。任务进度塑形只用于规划，不当作已获5分；本Tick阵亡则不给本Tick任务完成奖励。复活等待、重走路径与剩余Tick决定机会成本，不能仅把固定死亡罚换成1.8分。

例：双方各10HP互相普通击毁、均独占各自击杀奖，且本场此前D=0，则各记实际攻击10、击杀60、死亡扣60，D变10，只得0.3分，不能按名义20或忽略死亡。D=560、无新增而死一次变500，本次对抗分不下降，但仍损失行动时间和同分额度。

### P1：有限的对手情景与第二阶段规划

- 不把上帧defending当作本Tick确定防御；分别评估对手开火、防御、脱离等相关情景。先做本Tick精确结算和下Tick风险估计，不立即堆全局深搜或伪造行为概率。
- 先筛动作合法性/已知强制限制，再比较可活行动与危险行动；全都不可避免死亡时，仍比较攻击净收益。不是一律禁攻击或一律追残血。
- 收集、到点、伤害任务和战斗收益一起排序。能顺路完成多个目标时合并规划；目标保持阈值抑制每Tick改主意，前提失效立即重算。
- 临近终场降低无用的远期价值：路程超过剩余时间的目标剔除，已满项主要作为同分因素；不依据不可见对手总分判断“领先”。
- 保留balanced/fight/collect已登记枚举，在同一策略内自动选择行动；不通过写decision_config.json进行未经登记的自动人工式切换。

### P2：补齐事件收益和触发语义

优先爆炸/分裂/反伤/易伤的正确性，其次回血点、堡垒无双、辣椒主动策略。

| 机制 | 计划处理 |
|---|---|
| 爆炸/分裂 | 生效前提前撤离，不能等爆炸Tick再移动；分裂生效立即死亡/复活/强制WAIT，历史效果按绝对期限保留 |
| 反伤 | 本Tick若防御可产生反伤与击杀收益；无双按每个防御目标分别反伤，不能用一个固定反伤项概括 |
| 易伤 | 成功移动触发后下Tick生效；普通/无双伤害倍率作用于受伤者，环境与反伤不翻倍；移动失败不授予效果 |
| 回血点 | 成功入点才授予/刷新，不把站立WAIT当作触发；治疗发生战斗之后，不能救回战斗中已死车辆 |
| 堡垒/无双 | 存活且移动后在区内累计连续驻留，离开或死亡清零未完成进度；达标增益不能倒推到本Tick先前攻击；5×5全目标而非四向射线 |
| 辣椒 | 成功入点触发单Tick整行列火线，交点免疫该条；多火线统一分摊，普通伤害不计D、击杀池可计，需比较击杀收益与本车被其他火线命中的风险 |

所有事件坐标、时间、伤害/倍率参数来自公开公告经LLM解释及合法记忆；不写死教程的示例安排、不用关键词替代LLM。效果要带来源、时间和适用对象，模型推断与裁判真值分开；不知道的敌方效果不得当作已知。

模型接口扩展只增加上述机制必要字段；不要求公开感知出现协议没有的结构化事件。事件记录支持更新/撤销，避免旧模型误判被永久追加。公告只做原文缓存、场次隔离和重复传输控制，不用语义正则解析；相同Tick不同公告不得误删。

### P3：可解释日志与验收

每Tick记录选择原因、比较过的主要候选、预测净分/存活和不确定项，并对照后续公开回执；日志不含令牌。日志建议设采样/大小限制，不能阻塞500ms动作窗。

后续验证计划（本次未执行）：

1. 小场景：单人收残血/多人分摊/双方互杀、反伤混合贡献、同队去重、D=0/接近500/大于500、任务阈值后死亡不完成、已完成ID保留。
2. 事件场景：爆炸激活时移动无效、分裂原地复活扣分、易伤次Tick生效、反伤不翻倍、无双多目标、回血不能复活、辣椒不重复击杀。
3. 官方v1.1本地第二阶段500ms×500Tick，对照当前cf48837，固定测试配置作公平比较但绝不让策略读取配置。覆盖不同席位、地图、陪练组合、暂停/换场/重启。
4. 分别看资源分、对抗分、获资格任务分、死亡/击杀、无效动作和决策耗时p95/p99；不只看一场总分。目标本地决策p99低于20ms是待测工程目标，不是现有结果。
5. 真实模型可用后再测自然公告理解与裁判认可调用；此前无API时只声明结构/降级场景通过，不冒充正式资格。保留自己节点双向通信和回执证据供10/31 20:00前检录材料使用。
