# v1.1 规则变化与代码影响（内部备忘）

> 这不是提交材料，是给两个人看的工作备忘。  
> 依据：赛事规则 v1.1、通信协议 v1.1、裁判测试端教程 v1.1。

## 1. 最关键的变化

### 1.1 有效伤害 `D` 不再是旧版 300 门槛

v1.1：

```text
D(t) = max(0, D(t-1) + 本 Tick 实际攻击伤害 + 本 Tick 击杀奖励 - 60 × 本 Tick 死亡次数)
```

- 对抗得分：`15 × min(D / 500, 1)`，**500 才满分**。
- `D` 可以下降、可以为小数、可以超过 500；超过 500 仍用于同分比较。
- 感知里的 `score.effective_damage` 已经是这个调整后的值，程序不要再自己加/减一次。

### 1.2 击杀奖励

- 普通攻击、反伤、辣椒致死：每名被击毁车辆 **60 点击杀奖励**。
- 普通攻击/反伤：致死战斗批次中实际造成正伤害的贡献者，按队伍去重后平分。
- 辣椒：同 Tick 火线统一结算；实际造成正伤害的触发者按队伍去重后平分 60。
- 爆炸、世界分裂等环境死亡：**只扣 60，不发击杀奖励**。
- 战斗阶段已经阵亡的车辆，不再产生辣椒击杀奖励。

### 1.3 死亡扣除

- 每次死亡扣 **60 点有效伤害**，最低为 0。
- 在“本 Tick 实际攻击伤害 + 击杀奖励”全部计入后扣除。
- 世界分裂立即复活也扣。
- 资源和已完成任务保留。

### 1.4 任务

- 第二阶段三项任务**内容不固定**，以本场 `mission_text` / `missions` 为准。
- 伤害任务使用调整后的 `D`。
- 已完成任务不因后续死亡扣除而撤销。
- 任务检查在战斗和死亡扣除之后，只为存活车辆检查。

### 1.5 同 Tick 顺序

```text
攻击/反伤/伤害修正 → 分配实际攻击伤害和击杀奖励 → 死亡处理
→ 辣椒火线统一结算 → 死亡扣除 60 → 资源/任务检查
```

## 2. 对当前代码的影响

### 已经对齐的部分

- `decision/src/engine.cpp` 的 `damage_reward` 已按 **500** 门槛计算，不再使用 300。
- 决策输入 `s.score.effective_damage` 直接来自裁判感知，未重复加减。
- `effective_damage` 任务类型已映射。
- `missions` 类型映射支持 `normal_resources`、`high_resources`、`resource_value`、`effective_damage`、`reach`。

### 建议继续补的部分（B 负责）

1. **击杀奖励 60 的候选评分**  
   现在 `damage_reward` 只看本次名义伤害（20/10），没有把“击杀额外 60”单独算进候选收益。  
   这不会违规，但会让策略低估击杀价值。

2. **死亡扣除 60 的候选评分**  
   现在有死亡风险惩罚，但没有把“死亡还会扣 60 有效伤害”显式折进 utility。  
   可以加一个近似项，避免为了 20 伤害送命。

3. **v1.1 测试场景**
   - 80 + 20 + 60 = 160；
   - 随后死亡一次变 100；
   - 爆炸/世界分裂死亡只扣 60、不发 60；
   - 辣椒/反伤击杀平分 60；
   - 已完成伤害任务不因死亡扣除撤销。

4. **文档/报告**
   - 技术报告里写 500，不写 300；
   - 代码注释、README、测试说明同步。
