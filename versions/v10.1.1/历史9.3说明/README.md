# 校内 v9.3

程序版本 **9.3.0**，基于 `482c107` 的 v9.2，ROS 包和程序名仍为 `rmtc_bot9`。旧版完整保留在 `../v9.2`。

本版接入已验证的路径探索优化：第二阶段选定目标后，在没有可见敌人、没有危险场的条件下，从同长度最短路中优先选择能多看见未知格的下一步。不增加到当前目标的最短距离；有敌人或危险场时保留原先的风险和时间寻路判断。沿用 v9.2 的资源权重、战斗、任务和第一阶段算法。

## 测试结论

与修改前的 v9.2 在相同地图、席位、对手下比较：

| 场景 | 图数 × 席位 | v9.2 / 60 | v9.3 同策略候选 / 60 | 差值 |
|---|---:|---:|---:|---:|
| 冻结 9.1 对手，标准事件 | 32 × 4 | 39.945 | 40.360 | +0.415 |
| 混合对手，标准事件 | 32 × 4 | 42.186 | 42.476 | +0.290 |
| 冻结 9.1 对手，无事件，首批种子 | 32 × 4 | 40.046 | 40.507 | +0.460 |
| 冻结 9.1 对手，无事件，独立第二批种子 | 16 × 4 | 40.814 | 41.718 | +0.904 |

这是小幅优化，不是已证实的质变；两组带事件的地图配对置信区间仍覆盖 0。候选的 `bot.cpp` 与本版逐字一致，原始证据位于 [v9.2 资源审计](../v9.2/evidence/collection_audit_20261027/README.md)。本版正式构建、10 组回归及复跑一致性结果位于 `evidence/`，详见[验证报告](修复与验证报告.md)。

第一阶段保持原策略：前轮 48 张标准 20×20 图平均 39.33/40；24×24 压力测试平均 33.875/40。测试工具默认 24×24，测标准第一阶段必须显式传入 `--width 20 --height 20`。

前轮 500 ms/Tick 官方练习裁判的 45/60 属于 **v9.2**，不移记为本版成绩。真实统一 LLM、正式比赛对手和官方 v1.2 裁判验收尚未完成；离线事件使用理想结构化计划。

## 构建与运行

```bash
cd ~/ZKXWN/versions/v9.3
python3 scripts/verify_delivery.py
bash scripts/test.sh
bash scripts/build.sh
# ROS 域号按本次裁判实际配置设置
export ROS_DOMAIN_ID=27 ROS_LOCALHOST_ONLY=0 RMW_IMPLEMENTATION=rmw_fastrtps_cpp
bash scripts/run.sh A 2
```

需要 Ubuntu 22.04、ROS 2 Humble、C++17、CMake、colcon 和 libcurl 开发依赖。先停止同席位旧节点，再在新终端启动本版，确认日志 **`HERO 9.3.0`**；默认队名为 `HERO-9.3`。第一阶段使用 `bash scripts/run.sh A 1`。9 系列包名相同，不要同时叠加多个版本的 ROS 工作空间。

网关和令牌通过环境变量提供，不写入仓库；`RMTC_MODEL` 必须留空，仅使用官方统一网关。默认输出预算 1024，异步默认超时 15 秒。未配置真实网关的本地练习不等于取得正式 AI 资格。

离线复查：

```bash
build_core/rmtc_arena --stage 1 --width 20 --height 20 --maps 32 \
  --seed 20261110 --a 9.3 --b 9.1 --events none --threads 2
build_core/rmtc_arena --stage 2 --width 24 --height 24 --maps 32 \
  --seed 20261110 --a 9.3 --b 9.1 --field 111 --events standard --threads 2
```

该目录工具中的 `9` / `9.3` 表示当前 v9.3，`1` / `9.1` 表示冻结基线；不内置 v9.2 策略，比较 v9.2 时应分别运行两个目录的可执行文件，再比较各自 A 侧结果。
