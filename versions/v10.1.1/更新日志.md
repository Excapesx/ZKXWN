# 10.1更新日志

2026-10-28，基于10.0。

- 增加opening/adaptive/finish三个自动时段，500 Tick时分界为100、350；按本场总Tick缩放。
- 安全开局的资源基础估值提高20%，仍按可见对手到达时间和任务进度计算收益；扩展开局组合路线至第99 Tick。
- 有明确近资源机会时减少远处追猎；尾盘有安全可得分目标时减少巡逻/追猎。即时攻击和事件仍参与原有比较。
- 资源满120后降低额外采集的阻止对手收益，未完成采集任务的奖励独立保留。
- 增加阶段和系数日志；每Tick重置诊断，避免阵亡时显示旧采集状态。
- 冻结10.0决策核心并附原始/转换SHA，新增10.1对10.0的arena选项和17条阶段安全检查。
- 更新README、规则核对、学习指南、报告、交付清单和版本索引。第二阶段256场配对未证明稳定涨分，原始记录随包保存。

## 2026-10-28 任务变体与诊断工具

- 新增 `tests/v101_task_variants.cpp` 和 CTest `v101_task_variants`，覆盖：
  `normal_resources` 目标 3、`high_resources` 目标 2、`resource_value` 150、
  `effective_damage` 700、单个/多个 `reach`、混合任务、未知类型安全性。
- 新增 `scripts/analyze_bench.py`，汇总 arena 逐局 JSONL 的均值、分位数、
  低分地图、任务失败、死亡、等待和非法动作。它只读基准输出，不进入策略输入。
- 注意：arena 裁判仍固定生成 2 普通 + 1 高价值 + 中心 reach；大规模分数不是任务变体覆盖的证明。
