# 7.0 检查报告

检查日期：2026-10-24。检查对象：下载文件夹里的 `校内7.0` 的源码、测试、仿真裁判与报告，对照官方 v1.1 材料（`02_官方规则_v1.1_当前/` 三份 PDF、`03_官方练习包_v1.1/dist.zip`）。7.0 文件夹没有任何改动。7.0 的决策核心原样冻结在本包 `baseline_v7/src/rmtc7/` 中，所有对照都用它来跑。

## 结论

7.0 在“无事件、对手也是 7.0”的条件下打得不差，它报告里的数字在它自己的仿真器里也复现得出来。它的问题集中在三类：

1. **决策盲区**，换个对手或换个阶段就丢分：第一阶段探图太晚；第二阶段后期大量漫游；碰到不开火的对手会原地防御几百 Tick。
2. **模型链路很脆**，真实环境里可能整场用不上事件计划：模型输出只要有一处不合规就整份作废；结果在路上时公告一变就被当成过时丢掉；超时太短，超时后的重试还会白扣配额。
3. **证据覆盖不到它的结论**：仿真器没有任何随机事件，“事件局才是秒杀点”从来没被测过。

下面每条都给出位置、影响、8.0 的处理和证据。证据里的“同一输入对照”可以用 `./scripts/defect_cases.sh` 现场复现。

## 四、检查过、不是漏洞的地方

- **计分公式。** 练习包里的 `rules.txt` 写的是“对抗得分 15×min(D/300,1)、没有击杀奖励”。正式 PDF v1.1 写的是 D 满分 500、击杀奖励 60、每次死亡扣 60，PDF 更新记录里也写明“满分门槛由 300 改为 500”。7.0 按 PDF 实现，是对的。练习包的文本是旧版本，**建议向主办方确认练习网页的计分用的是哪一版**，避免拿练习分数去推正式成绩。
- **堡垒驻留口径。** PDF §8.5 写“每 Tick 战斗后存活且移动后位于堡垒内才累计驻留，连续 10 Tick 达标”，练习包写“连续停留”。两者在“站着不动算不算”上可能有分歧，7.0 和 8.0 都按“在区域内即累计”实现，正式口径以裁判为准。
- **世界分裂复活后有没有出生保护。** 规则没写。8.0 的离线裁判按“有 2 Tick 保护”处理，这只影响测评，不影响参赛程序。
- **AI 资格。** 7.0 的“本场 HTTP 2xx 即记资格、5 Tick 重试、最多 20 次”符合规则，8.0 保留。

## 五、没有改的

1. 追猎时两车在相邻两格来回晃（第 5 条）：8.0 没有专门处理，只保留了 7.0 的暂停规则。
2. 世界分裂十字墙只排除本车出生点（第 11 条）。
3. 第二阶段资源任务的完成率：“拿 1 个高价值资源”在 3×7.0 阵容里约 70%。没完成的局里，三分之二从头到尾没见过一个高价值资源；4 个高价值资源平均在第 16 Tick 前就被拿光。这是开局抢速度的问题，8.0 调高任务权重的实验没有任何效果，最终没有改。
4. 规则层面如果发现能“越权获利”的系统漏洞，按规则 §13 P7 应该向主办方报告而不是利用。本轮检查没有发现这类系统漏洞；上面的计分版本不一致属于需要确认的文档问题。
