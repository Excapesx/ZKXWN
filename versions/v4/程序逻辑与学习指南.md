# 程序怎么运行，练习时看什么

收到一帧感知后，程序先检查JSON、Tick、场次、自己的席位、位置和实体。解析失败会记录原因；它不会用不可信字段拼动作。换场次会清掉旧动作、地图相关状态和LLM请求；同Tick重发则使用该场次缓存动作，不多走一步。

合法感知送入地图记忆，只记自己看过的信息。资源消失、墙变化和回执由实际观测更新；不完整帧只补已确认信息。移动失败可能来自争格，因此先短期换路，不能直接认定那格是墙。

第一阶段主要找资源。程序先算到已知位置的距离，在剩余Tick预算内选路线；少量目标使用DP，较多目标用贪心加路线改进。没有资源就探索未知边界。地图之外没有被偷偷补成全图。

第二阶段会比较攻击、去资源或任务点、事件目标、防御和等待。攻击收益先估计伤害与击杀贡献，再扣预测死亡损失并应用500分项门槛；敌人动作未知，所以会比较不同情景。距离、风险权重和节奏奖励是为了选择动作的近似，最终HP、D与任务完成只认裁判。

LLM在线程里处理公告，主决策不用等待它。模型输出事件时间、区域与参数后，本地检查格式，再结合实际位置和回执跟踪效果。没有API时可以练本地收发与决策，但没有正式任务分所需的真实调用资格。回放示例里的plan是人工测试夹具，只用于练习工具。

动作发出前还要检查：阵亡只等待、保护期不能攻击、第一阶段不能攻击/防御、方向必须合法。下一帧的last_action告诉我们裁判实际执行了什么；只看到“发布动作”还不足以证明通信已完成。

可以按这个顺序练：先读一帧里的tick/session/self，再用本地回放看动作和reason；随后找src/rmtc2/bot.cpp中的stage1、stage2，尝试解释一次选择；最后打开回归测试，对照幻术和爆炸两个规则例子。暂时不用先读整个JSON依赖库。

构建后运行`./build_core/rmtc_replay 2 < examples/本地回放示例.jsonl`：`./`表示当前目录，`build_core`存放本地构建结果，`rmtc_replay`是回放程序，`2`选择第二阶段，`<`把文件内容交给程序。输出的action是要发给裁判的动作，reason是决策原因，decision_ms是这次本地处理耗时。
