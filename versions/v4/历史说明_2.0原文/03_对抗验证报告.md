# 03 · 对抗验证报告

> 一句话：**同图、同规则、同席位轮换，2.0 在四人局赢 75.0%，平均分 +9.57。**
> 增量来源很干净：对抗分 +10.3，代价是资源 −0.5、任务 −0.2。

---

## 1. 方法

### 1.1 裁判

自研仿真裁判（`tools/bench/referee.cpp`），实现 v1.1 中**可判定**的机制：

| 已实现 | 说明 |
|---|---|
| 移动 | 一格；越界/障碍失败；目标格被存活车占据失败；多车争同格全部失败 |
| 攻击 | 指定方向 1–2 格内**最近**目标；障碍不挡；保护目标吃 0 但挡枪 |
| 防御 | 本 Tick 受击 20 → 10 |
| 伤害分摊 | 同 Tick 多人打同一目标，过量伤害按名义比例分摊实际贡献 |
| 击杀奖励 | 每名死者 60，按"实际正伤害贡献者"按队去重平分 |
| 死亡 | 3 Tick 复活、回出生点、2 Tick 保护；**先加伤害与奖励，再扣 60**，下限 0 |
| 资源 | 存活车踩上即收集，不刷新 |
| 任务 | 仅对存活车判定，完成后不撤销 |
| 计分 | 阶段一 `40×R1/200`；阶段二 `30×min(R2/120,1) + 15×min(D/500,1) + 5×M` |

**未实现**：爆炸 / 幻术 / 天使恩泽 / 天下无双 / 世界分裂 / 火暴辣椒 / 洁身自好 / 潘潘的神。
因此所有对局**关闭随机事件**，双方条件相同。这一限制在 §5 单独讨论。

### 1.2 对手

**对手是 1.0 的真实代码，不是复刻。**

`tools/bench/legacy_adapter.cpp` 直接 `#include` 1.0 的
`Stage1Policy` / `Stage2Policy` / `DecisionEngine` / `WorldMemory` / `Planner`，
只做两件事：把仿真感知转成 `rmtc_bot::Perception`，按真实席位设置 `Config.team`。
**没有改一行决策逻辑，没有调任何权重。**

> 早期版本曾把 `Config.team` 写死为 "A"，导致 1.0 在 B 席位时把自己的对手过滤掉（看不见 2.0）。
> 该 bug 已修复并重跑全部数据 —— 下表是修复后的结果，对 1.0 有利。

### 1.3 对局设置

| 项 | 阶段一 | 阶段二 |
|---|---|---|
| 地图 | 20×20，障碍密度 13% | 24×24，障碍密度 13% |
| 资源 | 12×10 + 4×20 = 200 | 同左 |
| 任务 | 无 | 普通×2 / 高价值×1 / reach 中心点 |
| Tick | 100（100 ms） | 500（500 ms） |
| 席位 | A（单机器人） | A/B = 2.0 与 1.0 **轮换**，C/D = 通用贪心基线 |
| 地图数 | 300 | 300（每张图跑 2 次轮换 = 600 场） |

- 地图生成保证：四角出生点连通、资源可达、资源间曼哈顿距离 ≥2。
- 席位轮换的目的：抵消出生点位置带来的系统性偏差（每次统计 600 场）。
- C/D 的"贪心基线"是最近资源 + 贴身攻击，用来制造**真实的资源争夺**，避免两车空旷对刷。

## 2. 结果

### 2.1 第一阶段（300 张同图，独立采集）

| | 2.0 | 1.0 |
|---|---|---|
| 平均得分（满分 40） | **38.50** | 37.93 |
| 平均收集价值 | **192.5 / 200** | 189.7 / 200 |
| 胜 / 平 / 负 | **72 / 188 / 40** | 40 / 188 / 72 |

**解读**：两边都接近满分（p90 都是 40.0），因为 20×20 地图上 16 个资源足够密，100 Tick 基本能吃满。
2.0 的精确求解带来 **+0.57 分** 的稳定优势（胜场是负场的 1.8 倍），但**第一阶段不是决战场**。
这一条结论与"1.0 的束搜索很差"的直觉相反 —— 实测下来 1.0 的束搜索够用，真正的问题在第二阶段。

### 2.2 第二阶段 · 四人局（600 场，正式赛制）

| 指标 | 2.0 | 1.0 | 差 |
|---|---|---|---|
| **总分（满分 60）** | **34.78** | 25.21 | **+9.57** |
| 资源分 | 11.77 | 12.28 | −0.51 |
| **对抗分** | **10.54** | **0.26** | **+10.28** |
| 任务分 | 12.47 | 12.67 | −0.20 |
| 资源值 R2 | 47.1 | 49.1 | −2.0 |
| 有效伤害 D | **604.1** | 8.7 | +595.4 |
| 完成任务数 | 2.50 | 2.53 | −0.03 |
| 击杀 | **4.25** | 0.16 | +4.09 |
| 死亡 | 1.27 | 1.05 | +0.22 |
| **胜 / 平 / 负** | **450 / 7 / 143** | — | **胜率 75.0%** |

**这是本报告最重要的一张表。** 分项相加恰好等于总分（`11.77+10.54+12.47=34.78`），说明：

> 2.0 用 **0.71 分的资源+任务代价**，换来了 **10.28 分的对抗分**。

它没有"少干活去打架"，而是在同样的资源产出下，把 1.0 完全放弃的那 15 分拿走了 10.5 分。

### 2.3 第二阶段 · 1v1（600 场）

| 指标 | 2.0 | 1.0 |
|---|---|---|
| 总分 | **44.16** | 39.03 |
| 资源分 | 23.62 | 24.38 |
| 对抗分 | **5.86** | 0.09 |
| 任务分 | 14.69 | 14.57 |
| 胜 / 平 / 负 | **345 / 17 / 238** | 胜率 **57.5%** |

**为什么 1v1 优势收窄**：两个人的资源池各分 100，都接近 120 封顶，
"资源 30 + 任务 15"这两项几乎打平，只剩对抗分可争；而单个对手会跑、会复活，
2.0 只能把 D 打到 195（5.86 分），拿不到满分 15。

**结论**：2.0 的优势与"场上人数"正相关 —— 人越多，伤害越容易变现，而 1.0 越吃亏。
正式赛是四人局，因此 75.0% 是更相关的数字。

### 2.4 任务完成率（四人局）

| 任务 | 2.0 | 1.0 |
|---|---|---|
| 普通资源 ×2 | 84% | 85% |
| 高价值资源 ×1 | 69% | 72% |
| 到达指定点 | 96% | 97% |

两边都卡在"高价值资源"上 —— 全场只有 4 个高价值资源、4 支队伍抢，本来就有人抢不到。
2.0 在高价值资源上略低 3 个百分点，是"分了一部分时间去打人"的直接代价，属于预期内。

## 3. 性能

600 场四人局，每 Tick 记录一次决策耗时（微秒）：

| | p50 | p95 | p99 | max |
|---|---|---|---|---|
| 2.0 | **11.7** | **18.0** | **23.7** | 360.6 |
| 1.0 | 29.8 | 72.6 | 93.3 | 407.8 |

- 2.0 的 p99 是 **23.7 µs**，占 500 ms 动作窗的 **0.005%**；
- 相对 1.0，p50 快 **2.5 倍**，p99 快 **3.9 倍**；
- 两者的 max 都在几百微秒，属于操作系统调度抖动，不是算法问题。

> 注：这是 Windows + MSVC 19.51 Release 的数据。赛场是 Ubuntu + GCC，
> 绝对值会变，但"单次 BFS vs 每候选一次 BFS"的复杂度差异是结构性的。

## 5. 有效性威胁（必须说清楚）

| # | 威胁 | 影响 | 缓解 |
|---|---|---|---|
| 1 | **裁判是自研的**，不是官方 `rmtc_practice` | 绝对值可能与官方不同 | 只实现规则明文；关键结算（先奖后罚、过量分摊、争格失败）逐条对照 §5.2 编写 |
| 2 | **关闭随机事件** | 无法验证 LLM 链路与事件段策略 | 事件段只占比赛的一部分；04 文档要求赛前用官方练习端 + 真实网关做一次全链路自检 |
| 3 | **1.0 未针对 2.0 调优** | 可能低估 1.0 | 1.0 就是当前提交版本，未改一行；这正是"击败现有程序"的定义 |
| 4 | **地图分布自选**（13% 障碍、四角出生） | 与正式图不同 | 300 张随机图 + 席位轮换，降低单图过拟合 |
| 5 | **C/D 是贪心基线**，不是真人强队 | 资源争夺强度可能偏低 | 贪心基线在资源维度表现不弱（49.1 资源值，与 1.0 持平），争夺是真实的 |
| 6 | **1v1 结论偏弱**（57.5%） | 若正式赛出现 2 人局，优势变小 | 已如实报告，不宣称"全面碾压" |

## 6. 结论

1. **在正式赛制（4 人）下，2.0 对 1.0 的胜率 75.0%，平均分高 9.57。** 这个差距不依赖运气：600 场、300 张图、席位轮换。
2. **差距几乎全部来自对抗分**（+10.28 / +9.57），资源与任务基本持平。这与 01 文档的弱点分析（W3–W6）完全对应 —— 诊断和结果闭环。
3. **第一阶段只是"少赢半分"**，不是胜负手。真正该投入时间的是第二阶段的收益折算。
4. **1v1 只有 57.5%**，说明 2.0 不是万能的；它的优势建立在"多目标环境下伤害容易变现"这一事实上。
5. 所有结论都限定在"无随机事件 + 自研裁判"的条件下。事件段与真实网关链路仍需上场前实测。
