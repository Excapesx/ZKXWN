# 02 · 2.0 战术设计

> 设计原则只有一条：**所有决策在同一单位下比较 —— 真实比分增量。**
> 不引入"攻击权重 1.8""死亡罚 100"这类经验常数，参数只保留三个可解释的量。

---

## 1. 先把分数算清楚

v1.1 的分数结构（第二阶段满分 60）：

| 项 | 公式 | 上限 | **每单位的分数** |
|---|---|---|---|
| 资源 | `30 × min(R2/120, 1)` | 120 资源值 | **0.25 分 / 资源值** |
| 对抗 | `15 × min(D/500, 1)` | 500 有效伤害 | **0.03 分 / D** |
| 任务 | `5 × M` | 3 项 | **5 分 / 项** |

三个"汇率"就是全部战略：

- 一个普通资源（10）= **2.5 分**；高价值资源（20）= **5 分**；
- 一次普通攻击（20 伤害）= **0.6 分**；一次击杀（100 伤害 + 60 奖励）= **4.8 分**；
- 一项任务 = **5 分**（相当于 2 个高价值资源，或 8 次攻击）。

**由此可以直接推出三条战术结论**（不需要调参）：

1. **任务必做**。三项 15 分，是全场最便宜的 15 分（前两项顺手就完成，第三项是一次定向移动）。
2. **资源封顶 120 之后，资源分归零**。此时继续捡资源是纯浪费，只能去打伤害 —— 反之，若离 120 还远，资源的边际收益高于 0.6 分/次的攻击。
3. **击杀是最优攻击**。同样 5 次攻击，打满血目标得 3 分，打死目标得 4.8 分。所以"补刀"要单独提价。

> 1.0 的失败点就在第 2、3 条：它把伤害压到 0.6 分却把"可能受伤"记成 1.2 分，导致永远选不到攻击。

## 2. 决策流程

```
每 Tick（收到新感知）
 ├─ prepare()
 │   ├─ WorldMap::update()     学墙/空地/资源；阵亡帧不覆盖地图
 │   ├─ HazardField::apply()   合并 LLM 计划里的危险区（带 [start,end)）
 │   ├─ BlockMask              墙 ∪ 未来3Tick内禁行/致死的格子 ∪ 视野内敌车所在格
 │   └─ bfs()                  一次 BFS → dist[]（到各格的步数）+ first[]（第一步方向）
 │
 ├─ 阵亡 → wait
 ├─ stage==1 → 定向越野（§3）
 └─ stage==2 → 收益对齐（§4）
       ├─ 逃命（站致死格 / 下一 Tick 必死）
       ├─ 攻击候选（四方向射线，最近目标）
       ├─ 目标候选（资源 / reach / 模型建议 / 追猎）
       ├─ 防御候选（仅"残血且逃脱不掉"）
       └─ 取最大值 → 转成动作（含幻术方向补偿）
 └─ 合法性守卫（保护期不攻击、阵亡只 wait、方向必须单位向量）
```

**为什么是单次 BFS**：
BFS 从"自己"出发，得到 `dist[cell]` 和 `first[cell]`（从自己走向该格的第一步）。
之后无论是资源、任务点还是追猎位置，代价和目标方向都是 O(1) 查表。
1.0 是"每个候选目标各跑一次 BFS"，一旦危险区把 BFS 变成时空搜索，代价按候选数线性膨胀（见 W10）。

## 3. 第一阶段：定向越野

### 3.1 问题

```
已知：起点 s、已发现资源集合 N（|N| ≤ 16）、两两最短路 d(i,j)、剩余 Tick T
求：  访问序列 π，使 Σvalue(π) 最大，且 len(s→π₁→…) ≤ T
```

这不是 TSP（不要求回到起点），是**定向越野 / 带预算的最大收益路径**。

### 3.2 解法

- `|N| ≤ 13`：`dp[mask][last]` = 访问 `mask` 且停在 `last` 的最小步数。
  状态数 `2^13 × 13 ≈ 10.6 万`，转移 `×13`，单次求解约 1.4 M 次加法 —— 在 100 ms 窗口里可以忽略。
  目标值直接取 `mask` 的价值和，不做到达时间折扣。
- `|N| > 13`：按 `value / (绕路增量)` 贪心插入，直到预算耗尽。
- 重规划条件：资源集合签名变化、超过 4 Tick、当前目标失效。避免每 Tick 重跑 DP。

### 3.3 探索

没有已知资源时走向"最近的未探明边界"（`frontiers()`：已知空地且邻接未知格）。
这一条保证了"资源不会因为没看见而漏掉"——第一阶段的地图是同一张，探索本身就是收益。

### 3.4 与 1.0 的差异

| | 1.0 | 2.0 |
|---|---|---|
| 目标函数 | `Σ value·e^(-到达/50)` | `Σ value`（与真实得分一致） |
| 搜索 | 束搜索，最多 5 段，束宽 64 | 精确 DP（≤13），否则贪心 |
| 目标上限 | 16 | 16（受地图资源总数限制） |
| 重规划 | 每 Tick | 签名变化 / 4 Tick |

## 4. 第二阶段：收益对齐

### 4.1 资源的"含任务溢价"价值

```cpp
gain(r) = scarcity × 0.25 × min(r.value, 120 − R2)          // 基础：比分为 0.25/资源值
        + urgency  × 5.0    （若该资源能完成 high_resources 任务）
        + urgency  × (need==1 ? 5.0 : 2.0)  （若该资源推进 normal_resources）
        + urgency  × 5.0 × 进度占比         （若任务是 resource_value）
```

- `scarcity = 1.25`（场上只有 2 支队伍时）—— 人少则 120 封顶可达，资源更值钱；
- `urgency`：剩余 <180 Tick 时 ×1.8，<90 Tick 时 ×2.6 —— 任务有 deadline，越晚越贵；
- `R2 ≥ 120` 后基础项退化为 `0.002 × value`，只做同分 tie-break。

### 4.2 攻击的"真实比分"价值

```cpp
dmg   = 目标防御 ? 10 : 20                             // 防御减半
if (易伤生效) dmg *= 2                                 // 易伤翻倍
dmg   = min(dmg, 目标HP)
kill  = dmg ≥ 目标HP
delta = dmg + (kill ? 60 : 0)                          // 击杀奖励 60 计入
pts   = 0.03 × min(delta, max(0, 500 − D))             // 对抗分，封顶
pts  += kill ? 1.2 : 0                                 // 击杀节奏：对手 3 Tick 复活 + 回出生点
pts  += 伤害任务进度奖励（若存在 effective_damage 任务）
if (D ≥ 500) pts *= 0.30                               // 封顶后只剩补刀价值
if (自己残血 && 打不死对方) pts -= 1.0                  // 被反杀的期望损失
pts *= aggression                                      // 档位系数（1.0 / 0.7 / 1.4）
```

**关键点**：`500 − D` 出现在公式里，所以"还差多少分"自动影响激进度 —— 不需要额外调参。

### 4.3 追猎

只有当 `D < 500` 且敌人在 `hunt_radius` 内才生成追猎候选。
候选位置是"与目标同行/同列、距离 1 或 2"的格子（能立刻开火的位置）：

```cpp
expected = 0.6                       // 一次普通命中
if (目标HP ≤ 20) expected = 2.4      // 20×0.03 + 60×0.03 + 1.2
else if (目标HP ≤ 40) expected = 1.2 // 两下能杀
if (目标正在防御) expected *= 0.6
score = expected / (到攻击位的步数 + 1)
```

### 4.4 选择规则

所有候选（资源 / reach / 模型建议 / 追猎 / 攻击 / 防御）放在同一个池子里比 `score`，
**同一目标有 1.12 的滞回加成**（避免每 Tick 改主意导致原地抖动）。
攻击是"这一 Tick 就能兑现"的动作，因此直接与"每 Tick 收益"比较，不做距离折算。

### 4.5 逃命

站在"下一 Tick 致死或必死"的格子上时，逃命优先级压过一切（分值 1000）：
枚举四个方向，选"下一 Tick 伤害最小且非致死"的格子。无路可逃才考虑防御。

## 5. 战斗细节

| 场景 | 处理 |
|---|---|
| 目标在保护期 | 伤害 0 且挡枪 → 不攻击，绕开 |
| 自己处在保护期 | 不能攻击（规则 E_STATE）→ 只移动 |
| 目标防御 | 伤害 10（不是 20）→ 仍可能划算（0.3 分） |
| 洁身自好生效且目标防御 | 伤害 0 + 自己吃反伤 → 直接放弃 |
| 易伤生效 | 伤害 ×2 → 攻击价值翻倍，优先打 |
| 自己 HP ≤ 20 且打不死对方 | 扣 1.0 风险，通常转为走位/采集 |
| 双方同 Tick 互射 | 规则上"各计各的再扣死亡"，本地按 `D−60` 结算 |

## 6. 随机事件：只用 LLM，不做关键词匹配

### 6.1 调用契约

请求体（`node.cpp::maybe_request_llm`）：

```json
{
  "instruction": "Convert the announcement into this schema... half-open intervals... do not guess",
  "schema": {
    "hazards": [{"shape":"rect|cross","a":[x,y],"b":[x,y],"start":n,"end":n,
                 "damage":n,"wall":bool,"lethal":bool}],
    "effects": {"inverted":[s,e],"vulnerable":[s,e],"reflect":[s,e],"reflect_damage":n},
    "advice":  {"target":[x,y],"priority":1..3}
  },
  "request": {"tick":..., "map":..., "self":..., "mission_text":"...", "event_text":"...", "score":...}
}
```

**只把公告原文交给模型**；本地不做任何"包含'爆炸'就……"的解析（规则明令禁止）。

### 6.2 校验（`parse_plan`）

- 坐标必须在地图内（越界裁剪，矩形反向自动交换）；
- 时间窗必须 `0 ≤ start < end ≤ maxTicks+400`；
- 危险区数量 ≤ 32；
- `damage=0 && !wall && !lethal` 的条目直接丢弃（模型经常给出"建议避开但没有伤害"的空壳）。

校验通过才 `bot.set_plan()`；失败**保留旧计划**并重试（最多 2 次），不会因为一次坏输出变瞎。

### 6.3 危险场

`HazardField` 把计划展开成逐格记录（`start/end/damage/wall/lethal`），
规划时把"未来 3 Tick 内会禁行或致死"的格子并入阻挡掩码 —— 提前绕开，而不是等生效那一 Tick 才跑。

### 6.4 配额

- 开场即请求一次（满足"每场至少一次真实调用"的资格要求）；
- 事件文本或任务文本变化时请求；
- 未成功则每 20 Tick 重试一次，直到成功或硬阻塞（401 / `quota_exceeded`）；
- 全部请求在独立线程，主线程只读结果 —— **绝不阻塞动作窗**。

## 7. 工程实现

| 关注点 | 做法 |
|---|---|
| 动作窗预算 | 单次决策 p99 = 23.7 µs（500 ms 窗口的 0.005%） |
| 内存 | 每 Tick 一次 BFS，无时间维数组；24×24 地图下 < 10 KB 临时内存 |
| 线程 | 决策在主线程；LLM 在子线程，`mutex + condition_variable`，主线程 `poll()` 非阻塞 |
| 异常 | 解析失败不外抛；决策外抛则节点层退化为 `wait`，仍发布合法动作 |
| 幂等 | 同 Tick 重发感知 → 重发缓存动作，不推进策略 |
| 过期 | `tick < lastTick` 的感知直接丢弃 |
| 日志 | 不含令牌；每 25 Tick 打印一次动作/原因/LLM 状态/D/R |

## 9. 已知取舍与失败模式

1. **资源争夺是零和的**。四人局里资源池 200 被四家分完，2.0 的资源值（47.1）并不比 1.0（49.1）高 ——
   因为 2.0 用少量资源换来了满额对抗分。这个交换在 4 人局是赚的（+15 分换 −0.5 分），
   但在 1v1 里双方都能接近资源封顶，优势会收窄到 5 分左右（见 03 报告）。
2. **追猎依赖对手"配合"**。如果对手一直跑，追猎的期望收益会低于纸面值。
   当前的 `expected/(d+1)` 只是一个一阶近似，没有建模对手逃跑方向。
3. **事件处理只做"避让 + 建议目标"**，没有实现无双群攻、堡垒驻留、辣椒主动触发。
   这些机制需要完整的结构化事件语义，现有公告格式下容易误判，宁可不做。
4. **模型输出质量决定事件段上限**。本地只做结构校验，语义对错仍由模型负责 —— 这是规则的要求，也是风险所在。
