# 校内3.0

基于用户提供的校内2.0制作，适用官方规则v1.1。更新日期：2026-10-23。
这是完整源码交接目录，可复制到Ubuntu编译。程序沿用`rmtc2`命名空间和`rmtc_bot2`包名，避免启动脚本及接入路径改变；版本号为3.0.0。

## 本次改进

- 新场次先重置Tick、动作缓存、LLM计数与待处理计划；延迟到达的旧场次帧丢弃。
- LLM停止标志改为原子变量；退避可中断，HTTP支持取消且限制响应为1MiB。旧请求不能污染新场次结果或认证状态。
- 区分本场HTTP成功与事件计划解析成功。后者失败时，同一公告最多额外重试2次；尚未取得本场HTTP成功时仍按20Tick间隔请求。官方是否认可AI资格，以裁判诊断为准。
- 网关可填根地址或完整`/v1/chat/completions`地址；优先采用感知携带的近期公告集合，带上上一有效计划，拒绝过时请求的计划。
- 危险区保留独立时间窗，不把安全空档填成危险。重叠区伤害求和仅作为规划估计，复杂事件真实结算仍以裁判为准。
- 攻击估值纳入过量伤害分摊、多人平分60击杀奖、死亡扣60和500封顶；伤害任务收益需在预测存活时才加入。自身易伤不再误用于放大对敌伤害。
- 防御与普通攻击分别检查当前攻击阶段死亡上界；按正式顺序，移动不能躲掉本Tick已经结算的普通攻击。没有致死风险时不按每点受伤直接罚分。
- 补充核心回归和可注入模拟传输的真实LLM工作线程测试。

策略仍包含距离折算、攻击档位与小额击杀节奏偏好；不声称所有候选都是严格相同单位，也不声称全局最优。多敌开火为上界情景，不代表知道对手行动。

## 目录

`src/rmtc2`：决策、地图、协议、战斗计算；`ros2_ws`：ROS节点及HTTP工作线程；`scripts`：启动与检查；`tests`：回归；`更新日志.md`：修改原因与限制；`evidence`：实测输出与历史基准；`历史说明_2.0原文`：收到的2.0文档，只作历史参考；`02_官方规则_v1.1_当前`及`03_官方练习包_v1.1`：当前官方材料。

## Ubuntu操作

把整个文件夹复制到主目录后，打开终端运行：

```bash
cd ~/校内3.0
chmod +x scripts/*.sh
./scripts/test.sh
./scripts/build.sh
```

第一行进入文件夹，`~`是主目录；第二行允许执行scripts下的Shell脚本；第三行编译并运行不依赖ROS的核心与模拟LLM线程回归；第四行加载Humble并用colcon编译ROS包。需要已有C++17、CMake、ROS2 Humble、colcon和libcurl开发依赖。

启动自己的程序：

```bash
export ROS_DOMAIN_ID=27
./scripts/run.sh A 2
```

`export`把变量交给此终端启动的程序，27是练习公开ROS域，正式比赛换成裁判指定值；`A`是席位，`2`是第二阶段。第一阶段改成`A 1`。该命令只启动参赛程序，裁判需按官方教程另开终端运行。

启用AI前，在启动终端配置主办方提供的`RMTC_AI_GATEWAY`和本场`RMTC_TEAM_TOKEN`；真实令牌不要写进源码或截图。本包不含真实令牌。没有这些变量时保留本地决策，不能因此获得正式AI资格。

可调整档位仍为`balanced/collect/fight`，配置路径`ros2_ws/src/rmtc_bot2/config/decision_config.json`。只允许一个`decision_type`字段，格式或枚举错误会拒绝启动；临场修改与重启需遵守官方规则。
