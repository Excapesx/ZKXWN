# 校内4.0

基于桌面校内3.0检查和升级，日期2026-10-24，适用官方规则v1.1。
这是可独立复制的完整源码包。命名空间仍为`rmtc2`，ROS包和可执行节点仍叫`rmtc_bot2`，版本号已升为4.0.0。

先看[3.0检查报告](3.0检查报告.md)、[更新日志](更新日志.md)和[程序逻辑与学习指南](程序逻辑与学习指南.md)。

## 这版改了什么

- 修正幻术只反转移动、爆炸先于动作、分裂墙只在激活时致死等时序判断。攻击伤害先合计再封顶，增加无反击/可见敌人全开火两种情景的明确权重。
- 增加模型事件事实与实际回执结合的状态跟踪：幻术、爆炸、治疗点、堡垒/无双、分裂、辣椒、反伤、易伤。缺失历史时不虚构堡垒驻留；辣椒目标收益仍是位置不变条件下的估计。
- 强化协议边界：整数溢出、嵌套深度、重复位置标记、视野外实体和错字段均有检查；不完整观测不会抹掉已有墙/资源。
- 第一阶段增加预算内路线缩短与插入，缓存失效考虑地图变化，限制异常目标数量；脚下有资源时先等待采集。移动失败按真实回执短期避让，不记成永久墙。
- LLM输入异常和传输异常不会使工作线程直接退出；可取消旧场次请求，HTTP成功与有效模型输出分开；ROS入口增加回执、耗时、裁判拒绝计数日志。
- 增加独立JSONL回放工具、环境检查脚本、边界回归和自研模拟工具。

分数、HP、位置与任务完成状态始终以裁判最新感知为准。局部情景、距离折算、节奏收益等仍属启发式，不承诺最优策略或正式比赛胜率。

## 在Ubuntu开始

把整个文件夹复制到Ubuntu主目录，打开终端逐行运行：

```bash
cd ~/ZKXWN/versions/v4
chmod +x scripts/*.sh
./scripts/doctor.sh
./scripts/test.sh
./scripts/build.sh
```

`cd`进入该文件夹，`~`表示主目录；`chmod +x`允许执行scripts目录里的Shell脚本；`doctor.sh`只检查工具、ROS包、curl版本和变量是否存在，不打印令牌；`test.sh`构建标准C++工具并跑回归；`build.sh`加载Humble并构建ROS节点。需要已有Ubuntu22.04、ROS2 Humble、colcon、C++17、CMake、pkg-config和libcurl开发依赖。

启动第二阶段A席位程序：

```bash
export ROS_DOMAIN_ID=27
./scripts/run.sh A 2
```

`export`把变量传给此终端启动的程序；27是练习公开域，正式场换成裁判指定值；`A`是席位，`2`是阶段。第一阶段用`A 1`。裁判须按官方教程在另一终端启动。

启用LLM需要主办方给出的`RMTC_AI_GATEWAY`和本场`RMTC_TEAM_TOKEN`。网关可填根地址、以`/v1`结尾的根路径，或完整`/v1/chat/completions`。令牌只放启动环境，不写进源码或截图。本包没有真实令牌。模型返回有效内容仅是本地判断，正式AI资格仍看裁判侧成功计数。

现场档位文件是`ros2_ws/src/rmtc_bot2/config/decision_config.json`，只允许`decision_type`一个字段，枚举为`balanced/collect/fight`。修改和重启按正式规则执行。

## 本地回放

```bash
./build_core/rmtc_replay 2 < examples/本地回放示例.jsonl
```

前面的程序处理第二阶段，`<`把示例文件逐行送入标准输入；输出动作、原因和耗时。普通行可直接是官方结构的感知，也可用`{"perception":感知,"plan":结构化模型计划}`包装。本地示例计划是测试夹具，不能代替正式赛真实模型调用。

需要单独编译真实HTTP传输，可执行`cmake -S . -B build_http -DRMTC_BUILD_HTTP=ON`，再执行`cmake --build build_http`；该检查需要curl开发包，不等于已连通网关。
