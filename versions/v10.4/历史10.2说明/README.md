# 校内10.2候选版

程序 **10.2.0**，基于10.1提交 `a85c60a`；ROS包/程序仍为 `rmtc_bot9`。

本版将按规则计算的资源、伤害和条件任务增分与辅助偏好分列；用公开机会、累计到达、短组合路线、可延后完成的任务及风险选择动作。它是研究候选，当前未证明优于10.1，不建议据此直接替换正式参赛版。

## 已实现

- `score_model.hpp`：资源120→30分、伤害500→15分、合格任务每ID5分。统一预测增量并处理封顶、重复资源/任务、死亡扣分及缓冲。任务分始终标为资格成立时的条件估计。
- `opportunity_evaluator.hpp`：已知资源和坐标任务联合路线，最多12候选点、深度3、24 Tick组合预算、2000次展开；远处但来得及完成的单点保留。资源新鲜度和可见对手ETA只作启发式置信度。
- 比较同一路线延后一Tick的损失，避免将即时伤害与会被抢走的资源同等看待；当短资源路线之后仍可完成同一坐标任务时，保留其90%的后续价值用于机会比较，避免太早交不紧急的任务。该扣减是优先级辅助量，不改变任务实际5分。
- 死亡分损失只计算一次，另列复活期间机会损失的有界辅助估计。保留事件、保护、强制等待、攻击先于移动和场次隔离。
- `score_audit`记录得分空间、候选增分、辅助量、ETA、置信度、风险、淘汰原因和目标切换等；最多保留32候选、输出前12及汇总拒绝原因。置信度不是实际概率。

## 实验结果

Release/Debug各14组CTest通过，新模块30条检查通过。80张新地图×4席、每版320场独立对照：10.2 **41.495**，10.1 **41.716**；差值区间[-0.734, 0.284]。同场96局10.2 **40.340**、10.1 **41.247**，存在退步风险。第一阶段40新图逐图相同，均38.4/40。非法动作0。

## Ubuntu运行

```bash
cd ~/ZKXWN/versions/v10.2
python3 scripts/verify_delivery.py
bash scripts/test.sh
bash scripts/build.sh
export ROS_DOMAIN_ID=27 ROS_LOCALHOST_ONLY=0 RMW_IMPLEMENTATION=rmw_fastrtps_cpp
bash scripts/run.sh A 2
```

先停止旧节点、使用新终端，确认 `HERO 10.2.0`，感知后 `score_audit` 的variant应为2。正常脚本固定该编译候选；ROS默认也是2，现场JSON配置仍只有原登记的balanced/collect/fight，不增加任何运行时调参入口。

研究者在隔离构建目录用 `cmake -DRMTC_ABLATION_LEVEL=1/2/3` 比较源码中的离线编译分支；它不是比赛期间可改的参数。初始实验源码另存evidence/development/first_ABC_source.zip，避免把修正后的A/B/C误当成首次实验。

复现发布候选的一组比较：

```bash
bash scripts/bench.sh --a 10.2 --b 10.1 --mode seat --stage 2 --field 778 --events standard --maps 16 --seed 430000 --width 18 --height 18 --vision 4 --threads 2
```

需要Ubuntu22.04/Humble、C++17、CMake、Python3、colcon和libcurl开发依赖。规则PDF是v1.2，协议/练习二进制仍v1.1。本版未完成真实ROS构建、官方网关、正式AI资格或官方裁判整局验收。离线事件为理想结构化计划，不能转记为实机成绩。
