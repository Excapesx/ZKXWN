# 程序逻辑与学习指南（7.0）

## 一帧消息怎样变成动作

ROS 节点收到本席位的 JSON 感知后，先做**容忍式解析**：关键字段（tick、session_id、地图尺寸、self.position）缺失才丢帧；单条实体缺少 position/hp、team 不是 A–D、出现重复 team，都只跳过该实体并置 `observationComplete=false`，好实体继续使用。这样一条坏数据不会再让整场变成 WAIT。`hp` 越界钳到 0–100，`vision_radius` 越界钳到 0–4，错误类型的 `vision_radius` 仍然拒收。`self.team` 允许写长期队伍 ID，缺失时回退 `robot_id`；节点只在“看起来像席位字母且与本席位不符”时拒收。

帧通过后先过 `FrameGate`：同 Tick 重发不重复推进策略，直接重发缓存动作；旧场次被退休，迟到帧不会覆盖新场次；新场次清空地图、事件、追击记忆和旧模型请求的影响。随后把 `/referee/event_text`、`/referee/mission` 的话题缓存合并进感知：感知里的 `event_text`/`mission_text` 为空时用话题缓存，不把“公告是否刚好出现在这一帧”当作唯一来源。

决策引擎用当前感知更新地图，记录已见过的资源和障碍。未知区域保持未知；其他车在当前视野内的位置可以直接用，离开视野后旧位置只作为会过期的搜索假设。障碍不遮挡视野；阵亡帧没有周围实体。

`prepare` 每 Tick 重建静态 mask（永久墙、当前视野内敌车、失败边），再按是否有事件危险场选择距离场：

- 没有事件：普通 BFS，一次得到“到处走几步 + 第一步往哪走”。
- 有事件：**时间展开 BFS**。状态是 `(格, Tick)`，只有“到达该格的 Tick 仍生效”的墙/致死区才禁行；允许原地等待，让 10–30 Tick 的临时墙到期。旧版只把未来 3 Tick 的危险格写进静态 mask，第 4 Tick 后 BFS 又能穿过分裂墙，车会往墙里走。

第一阶段在剩余 Tick 预算内规划采集路线：脚下有资源就 WAIT 收集；已知资源用“距离 + 价值”的定向越野，n≤13 精确 DP；n=14–16 且剩余预算 ≤45 时也精确；其余贪心 + 2-opt + 插入；没有已知资源就用前沿探索。第一阶段只允许 MOVE/WAIT。

第二阶段先看已知前置事件：当前已经必死时 WAIT；下一 Tick 会危险时尝试提前离开。这里要分清“现在已经中招”和“下一 Tick 将中招”。**世界分裂**是特殊情形：被十字线击杀并立即复活的那一 Tick，裁判强制 WAIT；如果 `position_respawn` 且分裂事件在 ±1 Tick 内，直接 WAIT，避免发出必被 `E_STATE` 拒绝的 MOVE。

随后产生资源、到点任务、探索、事件收益和追击候选。资源最多向前看两站，给可能被抢走的第二站打折。任务按 ID 逐项检查；资源任务进度用 `score.resource_value` 的 10/20 增量计数，踩到从未见过的资源也不会漏记。天使恩泽只在“从点外成功移动进入点内”时刷新；堡垒目标取 3×3 中心；辣椒、天使、堡垒的权重比 6.0 高，但仍让资源在早期优先。

能打到人时，分别估计敌人暂不进攻、集中攻击自己和寻找攻击机会三种情景。每辆敌人只能选一个动作；出生保护目标仍然挡枪，后方目标不会被当成可命中。把实际贡献、击杀分摊和死亡扣除按同一批次算完，再比较攻击、防御及目标移动。对手下一步并不知道，三种情景也没有覆盖全部可能性；`incoming_damage` 是保守上界，不是预测。

最后由出口守卫再次检查：阵亡等待、保护期不攻击、第一阶段只移动或等待、方向必须合法。ROS 节点把动作连同原始 Tick 和 session_id 发出，并保存本 Tick 缓存。

## LLM 在这里做什么

随机事件公告交给异步 LLM 线程解释成经过校验的结构化事件。决策主循环可以继续运行，不等网络返回；迟到的旧场次结果会丢弃。7.0 的资格逻辑是：**本场本席位 HTTP 2xx 就算一次成功调用**，不要求正文非空；资格请求每 5 Tick 重试、最多 20 次，成功后停止。模型返回 `{}` 是合法的“无事件计划”，不会触发重试风暴；解析失败最多重试 3 次。401/额度耗尽仍硬阻塞。模型输出只做结构与范围校验，不用关键词匹配替代理解。

没有真实模型 API 时可以做核心练习，但不能把模拟成功当作正式比赛任务资格。

## 事件局的四个创意（规则允许，但要算清代价）

1. **世界分裂当传送/满血用**：分裂击杀是立即满血复活、只强制 WAIT 一 Tick，不是普通 3 Tick 等待。若当前 D≥560（死亡扣 60 后仍不低于 500）或 D<60（扣到 0 封底），且 HP≤30、离出生点很远，主动站上十字线可以换“满血 + 回出生点 + 1 Tick WAIT”。D 在 60–560 时死亡会真扣分，只在“不这么做必死/必丢任务”时考虑。7.0 默认只做“被分裂时 WAIT”，没有默认开启这条传送，因为它的收益高度依赖 D 和位置。
2. **洁身自好反伤 bait**：事件期间攻击正在防御的敌人，攻击者自身吃 12–20 反伤且打不动目标。低血但不至于死的车可以贴住敌人按 DEFEND，诱导对方开火，用反伤拿击杀奖励；7.0 已把反射加入战斗估计，但默认只在“致命但防御可活”时防御。
3. **堡垒窗口**：3×3 堡垒连续驻留 4 Tick 给 24 Tick 的 5×5、35/7 攻击。7.0 把堡垒目标提高到 8–12 分量级并取区域中心；进得太早会被集火，进得太晚拿不到完整窗口。
4. **天使与辣椒的时机**：HP<50 时，5×8=40 的回血通常比多打一下更值；辣椒交点自身免疫，但只应在同线有残血敌人时踩，不要为了 30 伤害走进另一条火线。7.0 的天使目标按“可回复 HP × 低血加成”计算，辣椒权重从 0.5 提高到 1.5，但仍让早期资源优先。

这些是**可选的战术扩展**，不是默认策略；默认策略仍以“资源 → 任务 → 伤害”的稳定顺序为主。正式场是否采用，要用裁判对分裂/堡垒/回血的最终口径和本场 D 值判断。

## 从哪些文件读起

| 文件 | 先理解的问题 |
| --- | --- |
| `src/rmtc7/types.hpp` | 一帧感知里允许知道哪些东西？动作如何表示？ |
| `src/rmtc7/parse.cpp` | 哪些字段是硬要求，哪些坏实体只跳过？空计划为什么合法？ |
| `src/rmtc7/bot.cpp` | 同一 Tick 有哪些候选，为什么选这个？分裂 WAIT、时间展开距离场在哪？ |
| `src/rmtc7/grid.cpp` | 未知、空地、障碍的区别；`bfs` 与 `bfs_timed` 的差别；定向越野怎样给第一步？ |
| `src/rmtc7/events.cpp` | 事件什么时候开始、到期；入点回血为什么要看上一帧？ |
| `src/rmtc7/battle.cpp` | 一人一个动作时伤害怎样同时结算；保护目标为什么挡枪？ |
| `ros2_ws/src/rmtc_bot7/src/node.cpp` | 感知话题、缓存、场次切换、AI 资格和动作发布怎样接起来？ |

## 命令拆解

`cd ~/校内7.0`：`cd` 是切换目录，`~` 是当前用户主目录。进入目录不会启动程序。

`chmod +x scripts/*.sh`：`chmod` 修改文件权限，`+x` 添加可执行权限，`scripts/*.sh` 匹配 scripts 文件夹中所有以 `.sh` 结尾的脚本。它不会安装 ROS。

`./scripts/test.sh`：开头 `./` 表示从当前目录找文件。脚本调用 CMake 构建，再用 CTest 执行五组本地检查。通过只说明这些用例通过，不能说明已连通裁判。

`./scripts/build.sh`：加载 Humble 环境，用 colcon 编译 `rmtc_bot7`。需要在 Ubuntu 安装相应依赖，Windows 的核心编译通过不代替这一步。

`export ROS_DOMAIN_ID=27`：为当前终端及它启动的进程设置 ROS 通信域。27 用于目前的公开练习。它不会启动裁判，也不会自动修改其他终端。

`./scripts/run.sh A 2`：启动 A 席位的第二阶段节点；A 和 2 是传给脚本的两个参数。其他席位换成 B、C、D，第一阶段把 2 换成 1。

`./scripts/bench.sh --a 7 --b 6 --others 6 --matches 100 --seed 83000 --robots 4`：离线比较 7.0 和 6.0，生成 100 张确定种子地图、四人局全席位轮换。它不连接 ROS，不访问模型，也不是官方比赛。

## 一次只学一个目标

先找一条回放输出，按“感知中的自己位置和 HP → 看得见的目标 → 候选动作 → 最终 reason”说明程序为什么这样走。再手动改一份测试夹具：把敌人 HP 改成 10，观察是否改选攻击；把一帧里的某条实体删掉 `position`，观察 6.0 与 7.0 的解析差异。夹具只是学习材料，不能写进正式参赛代码当作已知地图。
