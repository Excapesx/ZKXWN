# 校内8.0 更新日志

2026-10-24。以 7.0 为底子修改。官方材料版本不变，仍为 v1.1。

## 命名与部署

- 命名空间 `rmtc8`，ROS 包/程序 `rmtc_bot8`，版本 `8.0.0`，默认队名 `HERO-8.0`；构建、启动、测评脚本同步改名。
- 现场档位文件仍只含 `decision_type`：`balanced`（默认，追猎半径 10）、`collect`（半径 5，与 7.0 的 balanced 接近）、`fight`（激进系数 1.4、半径 10）。
- 所有决策参数写死在 `src/rmtc8/bot.cpp` 顶部的常量里，没有任何环境变量或隐藏参数通道。
- `RMTC_HTTP_TIMEOUT_MS` 默认值 2500 → 15000。这是部署参数，不是决策参数。

## 第一阶段

- 新增“观察点 + 已知资源”联合路线（`Bot::stage1_view_tour`）：
  - 贪心集合覆盖选出至多 4 个观察点，每个观察点的价值 = 未露面资源的平均密度 × 新覆盖格数 × 0.6。
  - 每个预计露面的资源预留 3 Tick 去捡。
  - 已知资源权重是观察点的 1000 倍，路线先保证吃下已知资源。
  - 至多 13 个节点交给精确 DP。
- 用规则公布的资源总数（12 普通 + 4 高价值，`Config::totalNormal/totalHigh`）判断还有几个没露面；全部露面后回到 7.0 的已知资源路线。
- 防摆动：上一 Tick 的观察点只要还有足够新格子就保留；“先去上一 Tick 的目标”的路线价值不变、长度只多 2 Tick 以内时坚持原目标。
- 只在视野 ≥ 3 且地图 ≤ 450 格时启用（规则标准为 20×20、视野 4），否则退回 7.0 的路线。
- `solve_tour` 在 n ≤ 16 时一律精确 DP（7.0 为 n ≤ 13 或预算 ≤ 45）。

## 第二阶段

- 开局路线（`Bot::stage2_route_goal`）：
  - 前 80 Tick、25 Tick 视野内，用与第一阶段相同的观察点 + 资源定向越野。
  - 已知资源按 7.0 的比分收益计值，并按可见敌人的到达距离打折。
  - 未露面个数 = 规则总数 − 本场见过的个数，随时间衰减（别人也在采）。
  - 能开火、血量低于 50、有天使/堡垒/辣椒事件时不出这个目标。
- 追猎半径 5 → 10（整个视野）。
- 巡逻搜索：开局 40 Tick 后、看不见敌人、D < 560 时，轮流去这些地方：任务到达点、地图中心、四个象限中心、由出生保护目击推断的复活点、按本车出生点镜像猜测的复活点。
- 识别不开火的对手（`Bot::is_passive`）：
  - 上一 Tick 与本车对齐在射程内、本 Tick 本车没有掉血，就给这些敌人记一次“没开火”，连续 3 次后不再计入 `incoming_damage`。
  - `forecast_battle` 的情景里也不让它们选攻击方向。
  - 一旦掉血，计数清零。
- `WorldMap` 记录本场见过的不同资源个数（`everSeenNormal/everSeenHigh`）。

## 事件计划解析（`parse_plan`）

- 逐条校验，坏条目只丢那一条。一条可用的都没有、或顶层字段类型不对时才返回失败（节点会有限重试）。
- 同时有 events 和 hazards 时只用 events，避免同一公告算两遍。
- 重复 id 改名保留；没有 id 时按种类、时间、坐标生成。
- 模型输出的 kind 归一：explosion/inversion/heal/fortress/split/chili/reflect/vulnerability，以及规则原文名字 illusion/angel/unrivaled/world_split/pepper/purity/pan 和对应中文名。只归一模型输出的字段，不解析公告文本。
- 缺的数值用规则正文公布的标准值补：爆炸 80、辣椒 50、幻术 50 Tick、天使 10 HP×10 Tick、堡垒驻留 10 / 伤害 50/10、反伤 20、易伤触发窗口 20 Tick；缺 end 时按规则标准持续时间补。
- 部分越界的矩形裁到地图内，完全在图外的拒收；点位必须在图内。
- 坐标接受 `[x,y]` 或 `{"x":..,"y":..}`；数值接受整数或可取整的小数。

## 模型调用链路

- `src/rmtc8/announce.hpp`（新）：
  - `AnnouncementLog` 把感知 `event_text` 与 `/referee/event_text` 话题上的每条公告按行去重、保序累积，整场只增不减，换场清空。
  - `PlanScheduler` 只在有新公告行时发计划请求，最小间隔 = max(3, 剩余 Tick / 剩余预算)，预算 90 次（配额暂定 100，留 10 次）。
- `node.cpp`：
  - 发给模型的是整场公告的最近 48 行。
  - 提示词只要求 `{"events":[...]}`，逐种写明字段含义。
  - 只丢弃比已采用计划还旧的结果。
  - `/referee/event_text` 订阅深度 1 → 128。
- `llm.cpp` / `curl_transport.cpp`：读超时把 status 置 −1，不重试（网关可能已扣配额）；新增 `http_successes()` 统计本场 2xx 次数，用于节流。
