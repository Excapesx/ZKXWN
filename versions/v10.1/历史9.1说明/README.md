# 校内9.1

基于已发布9.0（`c78f910`）制作的答疑适配补丁，程序版本为 **9.1.0**。重点是防止模型配置误用、明确输出预算和记录正式启动代码。第二阶段、战斗、计分与复活算法保持9.0实现；这次不宣称得分提高。

## 9.1改了什么

1. `RMTC_MODEL`或ROS的`model`参数只要非空就停止启动，并提示清除。LLM工作线程也拒绝非空模型名，请求体始终不含`model`字段，由统一网关选择默认模型。
2. `max_tokens`默认1024，未填或显式0都采用1024；负数报错。正数可以按赛前配置调整，例如512。512–1024是主办方建议值，未把它写成官方强制上限。
3. 启动日志标出`HERO 9.1.0`和输出预算；新增交付检查脚本，核对文件、Git提交、实际目录及可选的正式模型配置，不打印令牌或网关地址。
4. 补充答疑处理、更新日志、技术报告模板和正式验收步骤。9.0报告及日志归入`历史9.0说明/`，不算9.1测试结果。

异步调用、15秒默认超时和原重试策略保留。答疑示例0.78–0.99秒不是延迟保证；“300k”单位和关闭思考字段未知，没有猜测参数。`response_format`和`temperature`支持不等于必须使用，本版未新增这些字段。

## 在Ubuntu运行

仓库若在`~/ZKXWN`，使用：

```bash
cd ~/ZKXWN/versions/v9.1
python3 scripts/verify_delivery.py
bash ./scripts/build.sh
bash ./scripts/run.sh A 2
```

- `cd`进入9.1目录；`~`是Ubuntu当前用户的主目录。桌面独立包则先进入解压后的`校内9.1`。
- `python3`运行只读检查：验证本包清单，显示绝对目录、提交号及是否有未提交文件。没有Git信息的桌面包会明确标为未知。
- `bash .../build.sh`调用colcon编译ROS节点，需要Ubuntu22.04、ROS2 Humble、C++17、colcon、libcurl开发依赖；构建目录保留在本版自己的`ros2_ws`。
- `bash .../run.sh A 2`启动A席位第二阶段；A可换B/C/D，2可换1。裁判需要另行启动。

9.0和9.1的ROS包名相同。先停止旧节点，使用本版脚本和全新终端，避免同席位双发动作或加载旧工作空间。启动后检查日志中的9.1.0，不能只看进程名判断版本。

如旧环境设置过模型名，运行`unset RMTC_MODEL`：这句话是清除当前终端的旧变量。不要在启动命令中加`-p model:=...`。`export RMTC_MAX_TOKENS=512`表示把本终端的输出预算改为512；默认无需设置。

## 正式提交和启动要一致

```bash
python3 scripts/verify_delivery.py --expected-root "$HOME/ZKXWN/versions/v9.1" --expected-commit "实际封存的完整提交号" --require-llm
```

这里的提交号是占位符，须替换成最终封存提交。`--expected-root`核对绝对路径，`--expected-commit`同时要求提交匹配、全仓库干净、本版文件已被Git跟踪；`--require-llm`要求网关和令牌已设置，禁止自选模型，并检查数字配置。只读检查不会构建、启动或连接模型。

可以追加`--official-gateway "主办方确认的地址"`进行逐字比对；检查只能证明配置与所提供地址一致，不能自行认证该地址为官方服务。不要把令牌写进命令、截图、报告或仓库。

先构建再记录检查结果和启动日志。脚本检查源码与路径，不证明已有二进制由这些源码构建，也不证明真实AI资格成立。正式运行不得连接自备API、本地模型、mock或离线oracle；实际统一网关地址待现场确认。

## 规则对应处理

- 复活：以初始出生点做曼哈顿分层，按上右下左选合法格；障碍只排除落点；允许资源格；多车按A到D处理。离线裁判已有对应实现，正式决策仍以公开感知的实际位置为准。
- 保护：普通复活与分裂立即复活均已有2Tick保护实现，保护期禁止攻击/免伤，成功移动后按规则取消；两类复活在不同结算阶段发生，仍需官方裁判核对边界。
- 计分：继续使用裁判给出的调整后有效伤害，不因掉血就假定涨分，也不重复扣除历史死亡。死亡扣60及500伤害计分上限沿用。
- 公平性：资源公平性问答没有回答，程序不假设四席最近资源数相同。
- AI协作：赛前可用Agent；报告须如实说明贡献，队员需要能解释相关代码。不会Docker不作为当前阻塞项。
