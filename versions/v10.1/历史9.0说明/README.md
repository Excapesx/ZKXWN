## 在克隆的仓库中运行

需要Ubuntu 22.04、ROS 2 Humble、C++17、colcon和libcurl开发依赖。下列命令基于仓库放在`~/ZKXWN`：

```bash
cd ~/ZKXWN/versions/v9
bash ./scripts/test.sh
bash ./scripts/build.sh
bash ./scripts/run.sh A 2
```

`cd`进入本版的程序目录；`bash`执行对应Shell脚本。`test.sh`是检查，`build.sh`是构建，`run.sh A 2`启动A席位第二阶段；第一个参数可改席位，第二个参数`1/2`代表阶段。裁判需要另行启动，公开ROS域及网关按现场要求配置，不能据启动成功认定获得真实AI资格。

切换版本前先停止旧节点，避免同一席位多个程序同时发动作。真实令牌只放运行环境，不提交仓库。

## Ubuntu使用

本仓库中的9.0位于`versions/v9`；以下假设仓库克隆在Ubuntu的`~/ZKXWN`。

```bash
cd ~/ZKXWN/versions/v9
bash ./scripts/test.sh
bash ./scripts/build.sh
bash ./scripts/run.sh A 2
```

逐行作用：

1. `cd`进入文件夹；`~`是当前Ubuntu用户的主目录。
2. `bash ./scripts/test.sh`用Bash运行核心和模拟节点回归。它会生成本地构建文件，不会连接真实模型。
3. `bash ./scripts/build.sh`加载ROS 2 Humble，再用colcon编译`rmtc_bot9`。需要原有ROS、colcon和libcurl开发环境。
4. `bash ./scripts/run.sh A 2`启动A席位、第二阶段。`A`可按实际席位改为B/C/D，最后的`2`代表第二阶段。

使用`bash 脚本路径`能避免Windows复制导致的可执行权限丢失。脚本保留LF行尾。运行正式比赛还需主办方提供的公开ROS域、网关、令牌及现场连接方式；凭据不在本包中。不要在不清楚当前配置时重写系统网络或公开令牌。

## 离线对照

```bash
bash ./scripts/bench.sh --a 9 --b 8 --field 888 --maps 60 --seed 193000
bash ./scripts/bench.sh --mode duel --a 9 --b 8 --field 888 --maps 40 --seed 195000
```

第一条让9.0、8.0分别在相同条件下对抗三个8.0；第二条才让9.0、8.0同场。`--maps`为地图数，`--seed`为随机种子。成绩含各席位轮换，不能把全部记录都当作不同地图的独立样本。

事件模拟可加`--events standard`；`--noise 2`代表模型回答夹带一条错误事件，不是随机漏报。完整本次命令在`evidence/benchmark/summary.json`。

## 公告来源的取舍

9.0只把已接受、带当前`session_id`的感知中的公告和任务文本送给模型，并在本进程内按场次累积。没有场次标识的保留话题仅作诊断；它们不能因为“刚到达”就被认作本场新事件。

因此，首次晚加入或进程重启后，如果感知窗口已不包含早先公告，本程序可能缺少对应历史。应在官方裁判验证晚加入/重启行为；不能用旧场公告、隐藏配置或观赛全图补成比赛事实。当前机制解决旧话题污染，也明确保留这一信息可得性限制。
