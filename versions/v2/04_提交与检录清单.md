## 3. 上场前自检（8 项，缺一不可）

| # | 检查 | 怎么做 | 通过判据 |
|---|---|---|---|
| 1 | ROS 域与网络 | `export ROS_DOMAIN_ID=<本场>`、`ROS_LOCALHOST_ONLY=0`、`RMW_IMPLEMENTATION=rmw_fastrtps_cpp` | `ros2 topic list` 能看到 `/team_X/perception` |
| 2 | 感知在收 | `ros2 topic echo /team_A/perception --once` | 有 JSON，含 `tick`/`session_id` |
| 3 | **动作已发出** | 程序日志 `tick=... action=...` | 每 Tick 一条 |
| 4 | **动作被裁判接受** | 看诊断页"执行 Tick" | 执行 Tick 递增，不是"仅发布" |
| 5 | **回执正确** | 下一帧感知 `self.last_action.tick == 上一 Tick` | 不是连续 `E_TICK`/`E_SESSION` |
| 6 | **AI 真实调用成功** | 日志 `llm=ok`，诊断页"LLM 成功 N 次"≥1 | N ≥ 1（第二阶段任务分的硬门槛） |
| 7 | 事件解析 | 触发一条公告，看日志 `事件计划已更新：N 个危险区` | N ≥ 1 或明确"公告无伤害信息" |
| 8 | 席位/令牌 | 每场换席位后重设 `team` 参数与 `RMTC_TEAM_TOKEN` | 换了场次必须换 |

> 第 3–5 项是**规则要求的前置检录证据**，务必截图/录屏存档。

## 4. 与官方练习端联调

```bash
# 1) 起裁判（默认第二阶段，暂停状态）
tar xzf dist/rmtc_practice.tar.gz
cd rmtc_practice && ./start_referee.sh --port 8080
# 浏览器打开 http://127.0.0.1:8080

# 2) 起自己的程序（占 A 席）
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=27 ROS_LOCALHOST_ONLY=0 RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export RMTC_TEAM_TOKEN=practice-A
export RMTC_AI_GATEWAY=http://127.0.0.1:8080
./scripts/run.sh A 2

# 3) 网页点"开始 / 继续"
```

**验收三件套**（与通信协议一致）：

1. 页面"执行 Tick"持续增长；
2. 自己日志里 `llm=ok` 至少一次；
3. 比赛结束后页面的资源/伤害/任务与日志里的 D、R2 对得上。

**第一阶段**单独跑：`./start_referee.sh --stage 1` + `./scripts/run.sh A 1`。
第一阶段不调 LLM，`llm_enabled` 自动关闭（`stage != 2` 直接跳过）。

## 5. 现场切换 decision_type

规则只允许改 `decision_config.json` 的 `decision_type`，且必须来自赛前登记枚举。

```bash
cat ros2_ws/src/rmtc_bot2/config/decision_config.json
# {"decision_type": "balanced"}

# 切换（只能在暂停期间、经裁判批准后）
echo '{"decision_type":"fight"}' > ros2_ws/src/rmtc_bot2/config/decision_config.json
# 重启程序生效（重启须符合"每阶段最多 2 次"的限制）
```

三个档位的作用，登记时照抄：

| 值 | 作用 | 参数 |
|---|---|---|
| `balanced` | 默认；资源与对抗按真实比分权衡 | aggression 1.0，追猎半径 5 |
| `collect` | 偏采集；对手很强或自己残血时用 | aggression 0.7，半径 3 |
| `fight` | 偏对抗；资源被封顶或需要抢伤害时用 | aggression 1.4，半径 8 |

**不得**新增任何字段（节点只读 `decision_type`，多一个字段会抛异常并拒绝启动）。

## 6. 故障处置

| 现象 | 判断 | 处置 |
|---|---|---|
| 完全没有动作 | 感知解析失败 | 看日志 `感知解析失败(E_xxx)`；确认协议版本 |
| 动作发出但执行 Tick 不动 | 席位/场次不对 | 检查 `team` 参数与 `session_id` 回填 |
| 执行 Tick 涨但角色不动 | 撞墙/争格 | 正常，属 `move_failed`，不扣分 |
| `llm=authentication_failed` | 令牌错/过期 | 换本场令牌；401 不重试 |
| `llm=quota_exhausted` | 配额用完 | 自动降级为纯本地策略，任务分作废但资源/对抗分保留 |
| 程序崩溃 | — | 按规则登记重启（每阶段≤2 次），不暂停、不补时 |

## 7. 红线（违反即 T1–T3）

- ❌ 人工实时发动作 / 临场下策略指令（P1）
- ❌ 读全图、读他队感知、读观赛接口（P2）
- ❌ 冒用席位或令牌（P3）
- ❌ 异常流量/高频消息（P4）
- ❌ 绕过统一网关用别的模型（P5）
- ❌ 用正则/关键词解析事件替代 LLM（规则 §8.1 明令）

2.0 的实现里没有任何一处触碰上述红线：事件只走 LLM + 结构校验，地图只来自自身感知。
