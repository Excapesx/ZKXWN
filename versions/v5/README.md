## 在克隆的仓库中运行

需要Ubuntu 22.04、ROS 2 Humble、C++17、colcon和libcurl开发依赖。下列命令基于仓库放在`~/ZKXWN`：

```bash
cd ~/ZKXWN/versions/v5
bash ./scripts/test.sh
bash ./scripts/build.sh
bash ./scripts/run.sh A 2
```

`cd`进入本版的程序目录；`bash`执行对应Shell脚本。`test.sh`是检查，`build.sh`是构建，`run.sh A 2`启动A席位第二阶段；第一个参数可改席位，第二个参数`1/2`代表阶段。裁判需要另行启动，公开ROS域及网关按现场要求配置，不能据启动成功认定获得真实AI资格。

切换版本前先停止旧节点，避免同一席位多个程序同时发动作。真实令牌只放运行环境，不提交仓库。

可选对抗基准需显式指定4.0：

```bash
LEGACY="../v4" bash ./scripts/bench.sh --stage 2 --matches 100 --robots 4
```

# 校内5.0 · 对校内4.0 的对抗重构与实测结论

**结论先行：5.0 没有击败 4.0。**

400 场同图同规则实测（4 人局 200 图 × 2 次席位轮换 = 400 场）：

| 指标 | 5.0 | 4.0 | 差 |
|---|---|---|---|
| 平均得分 | **33.33** | **33.85** | −0.52 |
| 资源价值 | 47.7 | 46.9 | +0.8 |
| 有效伤害 | 673.2 | 658.2 | +15 |
| 完成任务 | 2.48 | 2.49 | −0.01 |
| 胜负 | 186 胜 / 8 平 / 206 负 | — | **46.5%** |

1v1（400 场）：5.0 = 37.96，4.0 = 38.71，178 胜 / 29 平 / 193 负（44.5%）。
第一阶段（200 图）：两者完全相同，38.38 分，200 平。

对称性对照（4.0 打 4.0）为 99 胜 / 2 平 / 99 负，说明裁判与席位没有系统性偏袒，
上述差距是真实的、但不构成"击败"。

## 这一版做了什么

以校内4.0 的决策代码为基底（保留其全部工程实现：事件跟踪、危险场、伤害批次、
协议边界检查），只在一处做结构性改写：

**第二阶段的目标选择，从"每 Tick 局部贪心"改成"整条路线先做带预算的集合 DP，再只跟队首"。**

- 新增 `plan_route()`：状态 = (已访问资源集合, 最后停在哪)，价值 = 计分点数而非原始资源价值，
  因此任务奖励（每个 5 分）会被路线规划直接计入，而不是靠"紧迫度系数"近似。
- 保留 4.0 原有的逐 Tick 贪心目标作为并列候选：路线只是"额外选项"，不替换即时机会。
- 其余决策（攻击估值、追猎、防御、事件处理）与 4.0 逐行一致，便于归因。

## 为什么"更好的算法"没有变成"更高的分"

三条经验证伪的假设，全部有实测数据，写在 [报告2_5.0设计与实测.md](报告2_5.0设计与实测.md)：

1. **用路线替换贪心** → 1v1 资源价值从 89.8 掉到 79.9。原因：对手是即时响应型，
   抢占近处资源时"按最优路线走"会输给"见什么拿什么"。
2. **资源清空后全球追猎** → 4 人局伤害没涨，资源掉 5 点，净亏。
3. **探索向地图中心收拢** → 4 人局胜率从 42.5% 掉到 40.8%，对手伤害反而涨到 1050。

根本原因在计分公式本身：`30·min(R/120,1) + 15·min(D/500,1) + 5·M` 是**凹函数**。
5.0 的资源均值更高（47.7 > 46.9），但因为封顶是凹的，**均值高、波动大反而拿分更低**。
所以"把平均资源做高"这个方向本身就不对，正确目标是**最大化"资源达到 120"的概率**。
这条写在 [报告4_结论与后续.md](报告4_结论与后续.md)，是目前唯一有说服力的下一步。

## 工程说明

- `src/rmtc3/`：纯 C++17 决策核心，无 ROS 依赖，命名空间 `rmtc3`，可与 4.0 的 `rmtc2` 同进程共存。
- `ros2_ws/src/rmtc_bot3/`：ROS 2 Humble 节点（4.0 的节点实现原样保留，仅包名与命名空间改名）。
- `tools/bench/`：自研 v1.1 裁判 + **直接编译 4.0 源码作为对手**的适配层（不改其决策逻辑）。
- `tests/`：4.0 的回归用例原样保留。

编译与对抗基准（Ubuntu 22.04 / ROS 2 Humble）：

```bash
./scripts/test.sh      # C++ 核心回归
./scripts/build.sh     # 构建 ROS 节点
LEGACY=../校内4.0 ./scripts/bench.sh --stage 2 --matches 200 --robots 4
```

Windows 上用 MSVC 单文件构建也可以（本次实测即如此，见 `evidence/bench_raw.txt`）。

## 边界说明

1. 自研裁判**不含随机事件**，也不模拟真实网关；双方条件相同，但**不能把这里的比分当成正式比赛胜率**。
2. 对手是 **4.0 的真实决策代码**，不是简化近似；适配层只做感知结构搬运。
3. 5.0 的失败是**可复现的**：同一 seed、同一地图集合、同一裁判，结果稳定。
4. 交付建议：**不建议用 5.0 替换 4.0**。它在这套裁判下的期望得分更低 0.5–0.8 分。
