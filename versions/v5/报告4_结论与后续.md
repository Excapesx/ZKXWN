# 结论与后续

## 一、结论

**5.0 没有击败 4.0，而且是稳定地略逊 0.5–0.8 分。**

| 场景 | 5.0 | 4.0 | 差 |
|---|---|---|---|
| 4 人局（400 场） | 33.33 | 33.85 | −0.52 |
| 1v1（400 场） | 37.96 | 38.71 | −0.75 |
| 第一阶段（200 图） | 38.38 | 38.38 | 0 |

不建议用 5.0 替换 4.0。这份交付的价值不在程序，而在**三件事**：

1. 一套可复现的对抗基准（对手是 4.0 的真实源码，含对称性对照）；
2. 三条被实测证伪的优化方向（见 `02`），可以省掉后人重复踩坑；
3. 一条关于**目标函数**的结论（见下）。

## 二、这次真正学到的东西：优化方向从一开始就错了

计分是：

```
得分 = 30·min(R/120, 1) + 15·min(D/500, 1) + 5·M
```

三项都带 `min(·,1)`，**是凹函数**。凹函数下：

> **提高均值不如降低方差。**

实测证据：5.0 的资源均值更高（47.7 > 46.9）、伤害更高（673 > 658），
但平均分更低（33.33 < 33.85）。因为 `E[min(R/120,1)] < min(E[R]/120,1)`，
资源分布越散，被 `min` 削掉的越多。

所以 4.0 和 5.0 都在优化一个**错误的量**（期望分项值），
而正确的目标是 **`P(R ≥ 120)`** —— "这一场能不能吃满资源分"。

## 三、下一步：唯一还有说服力的方向

### 方案 A：把目标函数换成"达满概率"

把资源阶段的决策从"最大化期望资源"改成"最大化 `P(R ≥ 120)`"。具体做法：

1. 用当前已知资源总量估算"能否吃满"：
   `可及总量 = Σ(仍在场的已知资源价值) + 未探索区域的期望价值`；
2. 若 `可及总量 < 120`，放弃"精打细算"，改为**最大化探索覆盖率**（找更多资源点）；
3. 若 `可及总量 ≥ 120`，改为**最短时间吃满 120**（这是个带截止时间的子集选择问题，
   比 TSP 简单：只要在 120 处截断）。

预期收益：资源分从 11.9（均值换算）向 30 靠拢的空间存在，
但需要先测出"实际可及总量"的分布，否则无法判断天花板。

### 方案 B：抢在封顶附近卡位

`min(R/120,1)` 意味着**第 120 点资源之后的一切资源对双方都是废的**。
如果能在自己吃满之后，把剩余资源**占住不捡**（站在资源格上），
对手就永远拿不到——这是 4.0 完全没有考虑的行为。

代价：站住 = 不移动 = 不拿伤害。是否划算需要实测。
（注意规则第 10.3 节：正常集火与自主战斗合法；但"约定互刷伤害/串通影响排名"违规，
所以只能做"占位"这种单方面行为，不能与对手形成任何默契。）

### 方案 C：把任务 15 分做成"必拿"

现在双方都是 2.48–2.49 / 3，平均丢掉 0.5 个任务（约 2.5 分）。
若能把"到达中心 + 2 普通 + 1 高价值"做成硬约束（前 200 Tick 内完成），
等于白拿 1–2 分。这是确定性收益，比在资源上搏 0.5 分稳。

## 四、不建议再做的事

| 方向 | 原因 |
|---|---|
| 继续调 `aggression` / `hunt_radius` | 扫描 1.0–2.5 全在噪声内（±1.5 分） |
| 重写决策核心 | 已试过一套完整的，4 人局只有 28–31 分 |
| 用全局路线替换贪心 | 实测资源 −5.9（1v1） |
| 资源清空后全球追猎 | 实测伤害反降、资源 −1.5 |
| 探索向地图中心收拢 | 实测胜率 −1.7pp、对手伤害翻倍 |

## 五、给接手的人

1. 先跑 `./scripts/bench.sh --stage 2 --matches 100 --robots 4 --a 4 --b 4` 确认基准对称；
2. 任何改动都跑 200 图 × 2 轮换，**单次 40–60 图的差异不可信**（噪声约 ±1.5 分）；
3. 改完先看**分项**再看总分：如果资源均值涨了但总分没涨，说明波动变大了，
   方向大概率错（本次的教训）；
4. 裁判不含随机事件，涉及事件的改动无法在这里验证，必须用官方练习端另测。
