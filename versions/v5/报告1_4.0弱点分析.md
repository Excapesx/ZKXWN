# 4.0 弱点分析（带行号，全部标注"实测是否可用"）

分析对象：`校内4.0/src/rmtc2/bot.cpp`（510 行）与 `grid.cpp` / `combat.hpp`。
判定标准只有一条：**能不能在同一裁判下变成分数**。仅"看起来不合理"的一律标为不可用。

---

## 一、实战可用（能变成分数，或至少能改变对手行为）

### W1 防御价值的符号是反的

`bot.cpp:448-450`

```cpp
const double deathCost = combat_points(damageScore) - combat_points(forecast_adjusted_damage(damageScore,0,0,1));
const double defendValue = defendFatal ? -deathCost : 0.0;
```

- `defendFatal` 为真 = **即使防御也会死**，此时却给了 `-deathCost`（负价值）；
- `defendFatal` 为假 = **防御能活命**，此时给 `0`。

结果是：**需要靠防御保命时它不防，防御没用的场合它反而更倾向防御**。
实测中 4.0 平均每场只防御约 3–6 次（我方 `defend_threat` 计数），绝大多数濒死回合选择继续对射。

**可用性**：可改变对手行为，但**没有转化成我方得分** —— 双方死亡数在 1v1 中几乎相同
（0.99 vs 0.95），说明这条被"同 Tick 互毁"抵消掉了。降级为"可利用但收益小"。

### W2 多目标时对自己伤害的估计偏保守

`bot.cpp:264`

```cpp
credit += std::min(own(solo), own(shared));
```

`shared` 假设"所有能打到该目标的第三方都会同时开火"，于是把预期战绩压到最悲观，
4 人局里这让 4.0 对**满血目标**的攻击估值长期偏低（0.6 分打底，被摊薄后可能为负），
所以它更愿意去打残血目标。

**可用性**：可预测 —— 它优先扑残血。**但**这也意味着它抢击杀效率高，
我们的实测里我方击杀 5.08 vs 它 5.06，基本持平。不可用。

### W3 追猎半径与经验价值极粗

`bot.cpp:424-432`

```cpp
if (damageScore < 500.0) {
    for (const auto& e : p.entities) {
        if (manhattan(e.pos, p.self) > hunt_radius_) continue;   // 默认 5
        double expected = 0.6;
        if (e.hp <= 20) expected = 2.4;
        else if (e.hp <= 40) expected = 1.2;
```

- 只认 5 格内；
- 价值只有 3 档（0.6 / 1.2 / 2.4），与"还差多少到 500 封顶""我是否打得过"都无关；
- 目标格取 `e.pos ± dir*step`（`bot.cpp:433-442`），不检查该格是否是墙或危险区。

**可用性**：**已验证不可用**。我把追猎改成"按剩余封顶额度 × 胜负比 ÷ 走位成本"的连续估值、
并放开到 6 格，4 人局伤害只从 673 → 697（+24），资源掉 1.3，净负。

### W4 未知格当作可通行

`bot.cpp:83`

```cpp
for (const auto& wall : mem_.walls()) mask_.set(wall, true);   // 只挡已知墙
```

未观测格在 BFS 里是**可走的**，所以到远处资源的距离是乐观估计；撞墙后靠
`failed_edges_`（`bot.cpp:100-103`）事后封边 2 Tick。

**可用性**：**不可用**。这是"用乐观距离 + 事后修补"的经典组合，
4.0 在 200 图里没有出现明显卡墙（决策耗时 p99 34 µs，说明没有反复重算）。

## 二、看起来像弱点、实测不成立

### W5 第二阶段没有路线规划（只有逐 Tick 贪心）

`bot.cpp:378-394`：每 Tick 对每个已知资源算 `gain/(d+1)`，取最大。

这确实不是全局最优。我据此重写为"带预算的集合 DP"，**结果更差**：

| 方案 | 1v1 资源价值 |
|---|---|
| 4.0 原版（逐 Tick 贪心） | **89.8** |
| 5.0 用路线替换贪心 | 79.9 |

原因是**对抗改变了最优解**：路线规划假设资源归我，但在 1v1 里近处资源是抢的。
"见什么拿什么"的反应速度比"按最短路走"更值钱。这是本次最重要的负面结论。

### W6 资源清空后没有把"找人"当目标

`bot.cpp:424` 的追猎只在 5 格内生效，资源清空后经常整场找不到人（我方 explore 占 82%）。

我以为"资源清空后全球追猎"能白拿伤害，实测：4 人局伤害 673 → 597（反而降），
资源 −1.5。原因是跨图追击时对手一直在移动，**约 0.4 次攻击/追 10 格**，纯亏。

### W7 `mission_urgency` 在尾盘把资源价值放大到 2.6 倍

`bot.cpp:202-212`。看起来会导致尾盘为 10 点资源跑很远。实测 4.0 的任务完成率 2.49/3，
我方 2.48/3，无差异。

## 三、结论

4.0 的决策在**这套计分规则下已经接近局部最优**。它能被指出的"错误"大多是
**在对抗环境里反而正确**的设计（例如不走最优路线，是为了抢近处资源）。

真正剩下的空间不在"决策更聪明"，而在**目标函数本身**：

```
得分 = 30·min(R/120, 1) + 15·min(D/500, 1) + 5·M
```

三项都带 `min(·,1)`，**是凹函数**。凹函数下"提高均值"不如"降低方差"：
本实测里 5.0 的资源均值更高（47.7 vs 46.9），平均得分却更低（33.33 vs 33.85）。
两个程序都没有在优化"达到 120 的概率"，这才是唯一未被开发的维度。
