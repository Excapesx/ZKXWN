# 校内7.0 更新日志

2026-10-24。程序基于 6.0 审阅，保留其采集/越野/战斗主干，修改规则边界、事件时序、AI 资格和异常输入处理。官方材料版本不变，仍为 v1.1。

## 输入与部署

- 命名空间 `rmtc7`，ROS 包/程序 `rmtc_bot7`，版本 `7.0.0`；构建、启动、对比脚本同步。
- 现场档位文件仍只含 `decision_type`，支持 `balanced/collect/fight`；不新增坐标、动作或隐藏参数。
- 新增 **时间展开 BFS**：临时墙只在“到达该格的 Tick”仍生效时禁行；静态 mask 只放永久墙和敌车。
- 新增 `/referee/event_text`、`/referee/mission` 订阅；感知字段为空时回退到话题缓存；新场次清空旧公告缓存，避免上一场 retained 文本污染本场。
- 默认队名改为 `HERO-7.0`。

## 感知与计划

- 单条坏实体只跳过，不整帧拒收；缺 `visible_entities` 视为空帧并置 `observationComplete=false`，不清地图记忆。
- `self.team` 接受长期 ID，回退 `robot_id`；节点只在“看起来像席位且与本席位不符”时拒收。
- `hp` 越界钳到 0–100，`vision_radius` 越界钳到 0–4；错误类型的 `vision_radius` 仍拒收。
- `last_action` 回执不合法时忽略，不再整帧失败。
- `parse_plan("{}")` 是合法空计划；无事件/资格确认不再触发重试风暴。
- 资源任务进度用 `score.resource_value` 的 10/20 增量计数，不再依赖“是否刚好记得同格资源”。

## 规则与事件

- 世界分裂导致立即复活的那一 Tick，若 `position_respawn` 且分裂事件在 ±1 Tick 内，强制 WAIT，避免 `E_STATE`。
- 天使恩泽只认“从点外成功移动进入点内”；在点内来回移动不刷新。
- 天使、堡垒、辣椒的战术目标权重提高；堡垒目标取 3×3 区域中心，而不是左上角。
- 敌方火力预测中，出生保护目标仍挡枪：后方目标不再被错误视为可命中。
- 第一阶段保持 6.0 的预算路线与探索策略；`solve_tour` 仍 n≤13 精确、n>13 贪心，避免 16 节点全知 DP 在“资源还没看全”时反而降低发现率。

## AI 资格与降级

- 本场本席位 HTTP 2xx 即记资格，不再要求响应正文非空。
- 资格请求每 5 Tick 重试一次、最多 20 次；成功后停止。
- 事件计划失败最多重试 3 次；`{}` 不再算失败。
- 401/额度耗尽仍硬阻塞；模型输出仍只做结构与范围校验，不做关键词替代。

## 验证

- 五组测试 4016 项断言，零失败：141 旧核心、11 模拟 LLM 线程、613 既有边界、3228 情景/性质、23 新增 7.0 契约。
- 第二阶段 7 对 6 共 4120 局：1×7 对 3×6 1200 局、2v2 1200 局、矩形 720 局、对称 600 局、1v1 200 图/400 局；第一阶段 100 图；全部非法动作 0。
- 无事件对称基准 7.0 与 6.0 同分（38.63 对 38.63）；对 3×合法贪心 37.91 对 24.42，+13.49，严格胜率 83.5%。
- 本机决策 p99 约 0.07 ms、最大约 0.4 ms，不含 DDS、模型和 ROS 发布链路。

## 仍未完成

Ubuntu ROS/curl 完整构建、真实网关、官方裁判回执/换场次、随机事件整场和正式 AI 资格均待验收。无事件基准不能证明“秒杀 6.0”；7.0 的增量在事件局和异常局，必须用官方测试端复核。没有将 7.0 推送到 GitHub。
