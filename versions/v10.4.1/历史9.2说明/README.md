# 校内9.2

程序版本 **9.2.0**。从9.1（d9027c8）独立制作，ROS包/程序名继续使用`rmtc_bot9`，纯C++命名空间继续用`rmtc9`。历史9.1完整保留在仓库兄弟目录。

这版重点解决昨天第二阶段后半场的目标断档，并补上v1.2偏移堡垒的规划与验证。它不是一次已证实能“压倒性获胜”的升级：对照得分整体接近9.1，部分场景略有提高，部分略低；结果见下面的表和[验证报告](修复与验证报告.md)。

## 为什么9.1会停住

昨天A完成三个任务后，伤害量达到515。旧策略在500后停止主动追击；远处敌人仍可见时又关闭巡逻。当探索前沿也为0时，只剩`stage2_explore`等待。原始实录action Tick297–499连续203次wait，约101.5秒。

把501帧公开感知送回冻结9.1，500条动作与实录逐条相同，确认了上述分支。给9.2相同历史感知时，末203帧大多选择继续追击或巡逻。历史感知不会随新动作改变，因此这个结果只验证目标断档修复，不能换算成新比分或真实走位成功率。

## 这次如何选择动作

1. 先遵守死亡/复活、保护和当前事件时序，再处理资源、任务与攻击。
2. 对抗分仍在500伤害量封顶。策略把560作为一次死亡扣60的规划缓冲目标；560是本队策略阈值，没有修改裁判计分。达到500后只追有利血量或可补刀目标，避免为缓冲主动追强敌；任务要求更多伤害时继续评估。
3. 看见远敌不再关闭全部巡逻候选。对缓冲阶段的移动比较下一格多车火力；没有收益目标时可减少暴露，缓冲足够后明确进入`score_guard`防御守分。守分仍需真实对手检验。
4. 天下无双区域从公告矩形确定，模型提示明确禁止猜地图中心。选择矩形内最近可达格，不强求走中心；进入后维持驻留，临近结束也保留已有占领进度。
5. 日志增加`frontiers/goals/unsafe_goals/enemies/combat_objective/wait_streak`。探索等待细分为空前沿、无安全前沿、首步无效，方便继续排查。

离线工具也增加了9.1冻结基线、移动/等待统计，校验导入地图的尺寸、坐标、资源ID和出生点。`unrivaled.rect`/`center`是自研离线工具为偏移堡垒测试提供的扩展，不代表旧官方练习端接受这些字段。

## 规则与证据

当前规则PDF是[赛事规则v1.2](01_赛事规则_v1.2/)，随包协议、教程和官方练习二进制仍为v1.1；旧目录名中的“当前”属于继承命名，以此说明为准。[规则适配说明](v1.2规则适配说明.md)记录了差异和仍待验证的项目。

官方统一网关默认模型限制、默认1024输出预算、异步请求和15秒默认超时沿用9.1。请求不含`model`，非空自选模型配置被拒绝。正式运行只使用主办方统一网关，不能用本地模型、自备API、mock或离线oracle取得资格。

Windows MSVC19.51的Release、Debug构建及各9组回归通过，包含生产节点的ROS替身/注入HTTP验证。尚未在Ubuntu重新构建9.2，也没有完成真实DDS、真实统一LLM或v1.2官方裁判验收。昨天的实机成绩属于9.1。

## 在Ubuntu使用

先停止同席位旧节点，打开新终端，再执行：

```bash
cd ~/ZKXWN/versions/v9.2
python3 scripts/verify_delivery.py
bash ./scripts/build.sh
export ROS_DOMAIN_ID=27 ROS_LOCALHOST_ONLY=0 RMW_IMPLEMENTATION=rmw_fastrtps_cpp
bash ./scripts/run.sh A 2
```

第一行进入9.2；第二行只读核对文件清单；第三行用colcon编译ROS节点；第四行按昨天练习环境设置ROS通信，正式场以主办方要求为准；最后启动A席位第二阶段。裁判需另开终端启动。启动日志必须显示`HERO 9.2.0`。上传GitHub和桌面封装不会自动更新Ubuntu。

网关和令牌通过运行环境设置，不写入仓库。不要填写模型名：如旧终端曾设置过，执行`unset RMTC_MODEL`。缺真实网关时，本地移动/战斗可以练习，真实模型资格仍然未验证。

## 自己复查

```bash
bash scripts/test.sh
python3 scripts/compare_recorded.py --build build_core
bash scripts/bench.sh --a 9.2 --b 9.1 --field 111 --maps 16 --events standard --seed 20261027
```

第一条构建并运行9组回归；第二条重放昨日公开感知，核对9.1动作一致性和9.2断档修复；第三条以相同地图、席位、阵容对照两个版本。`111`指其余三台使用冻结9.1；`9`是9.2的工具别名，`1`是9.1。结果不连接ROS或真实LLM。

交付后用`python3 scripts/verify_delivery.py --expected-root "$HOME/ZKXWN/versions/v9.2" --expected-commit "实际完整提交号"`核对实际路径、代码清单、干净Git。模型配置检查和正式验收模板见[正式验收说明](正式验收与技术报告模板.md)。
