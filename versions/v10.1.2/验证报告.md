# 10.1.2 三任务检查与验证

基线为队友提交1fa80d0的10.1.1。确认任务为普通资源至少2个、高价值资源至少1个、到达当场指定坐标。实现继续读取结构化missions及completedIds，不硬编码任务ID、数量或坐标；截图[12,12]是练习基准。

## 代码审计和改动

普通/高价值资源原已有任务进度估值、公开历史采集计数及完成ID检查，本次没有提高资源权重。到点任务原来只给距离大于0的目标生成候选，遇到首次感知就在任务点或任务刚下发到脚下时，可能立即离开，错过行动后任务结算。

新版本给此类未完成任务一次原地结算机会：安全且攻击收益为正时原地开火，否则在防御可存活时防御。先执行已有的分裂强制等待、当前事件死亡和逃离危险判断。每任务ID仅主动驻留尝试一次，避免资格缺失或回执迟到造成永久停车；不把尝试当作任务完成，仍以裁判completedIds为准，新场重置。

审计时曾考虑增加截止权重，后发现原有BFS已经限制剩余Tick，故最终撤回权重/路线调整。最终寻路、任务估值、战斗与分时参数沿用基线。剩余时间和最终Tick边界仅补回归检查。

## 验证

- Windows MSVC Release，核心及ROS替身/模拟HTTP回归16/16通过。测试镜像仅在CMake移除实际CURL传输测试，运行源码与发布候选逐字节一致；Windows显式使用/utf-8 /EHsc。实际HTTP传输测试未运行（本机没有用于该构建的CURL开发配置），完整发布CMake保留该测试。真实Ubuntu/ROS、官方裁判和真实LLM未验证。
- 新增9项场景检查：脚下目标、回执缺失不永久驻留、新场重置、已完成任务、最后Tick到达、超预算目标、致命来火、安全补刀、三任务联合执行及合法动作（最后一项联合场景含两条断言，共10条判断）。基线隔离探针在脚下目标及新场重置场景失败，新版通过。
- 三任务联合场景使用非默认坐标[6,1]、2个普通资源、1个高价值资源；离线裁判确认三项完成、非法动作0。
- 最终冻结后的新种子103150000/103151000：第二阶段无事件/标准事件各10图，每图四席80对照。只替换指定席位，其余三席均为冻结的10.1.1。第一阶段另10图种子103152000。旧版仅隔离命名空间，以公开感知适配，事件计划由公告后2Tick的理想oracle提供。
- 这批常规随机地图没有测出分数提升；脚下目标的正确性由定向场景证明。不得据此宣称全面变强。初版40图属于开发检查，数据保留在本地work，不混入最终结果。

## 保留问题

资源计数依赖连续公开历史；缺帧或中途接入时可能无法还原精确采集种类。安静对手风险启发式沿用原版。任务坐标与数量仍以正式公开感知为准；本版没有硬编码第三项[12,12]。
