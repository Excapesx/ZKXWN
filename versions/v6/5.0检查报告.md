# 5.0检查报告

检查日期：2026-10-24。输入为桌面HERO中的校内5.0和4.0。原文件夹保持原样，6.0另存。

## 确认的问题

| 位置 | 问题及影响 | 6.0处理 |
| --- | --- | --- |
| 第二阶段攻击选择 | 只有攻击估值大于0才进入比较。防御、移动同样会死时，可能丢弃损失更小的还击 | 比较负收益候选；当前前置事件已必死时仍等待 |
| 攻击估值 | 把“第三方攻击同一目标”的分摊估计与“所有敌人同时攻击我”的受击估计混在一起，情景不相容 | 每个情景中每辆敌车只选一个动作，按同一批次结算 |
| 事件与战斗交界 | 估计时没有统一先剔除已被已知前置事件击毁的敌车，可能虚算射击、占位或挡枪 | 战斗预测、当前射线及规划占位过滤已知前置死亡 |
| 5.0长路线 | 把长期资源当作仍可取得，分配未来收益给队首；最多10个节点还会挤掉低即时价值的任务点 | 改成逐帧两站短程比较，折扣可能被抢走的第二站 |
| 任务选择 | 多处只找第一条同类型任务；路线在资源分封顶后不再纳入资源，即使还有相关任务 | 逐个任务ID检查；资源封顶后仍考虑未完成任务 |
| 探索及追击 | 只在没有其他目标时探索；缺少近期视野记忆，反复追同速移动目标 | 信息增益候选、会过期且能被当前视野否定的敌人记忆、短期拦截和追击冷却 |
| 第二阶段脚下资源 | 目标距离为0被跳过，可能移动离开而丢掉收集机会 | 可以留在原位收集 |
| 模拟器输入 | 缺少真实成功/失败移动回执；阵亡帧仍带周围实体，不符合正式公开感知 | 加回执和复活标记；阵亡帧清空周围实体 |
| 模拟基线 | 贪心对手可能在出生保护期攻击；只对比上方两席互换 | 修正保护期动作，增加全部12种有序席位安排 |
| 版本标识 | 5.0的ROS包仍标4.0.0 | 本版统一为6.0.0及rmtc_bot6 |

负收益还击做了原版4.0与6.0的实际同输入对照：己方HP10、D100、相邻敌车HP100。4.0选择移动，估值-1.8；6.0选择攻击，估值-0.75。这里的受击是情景假设，不能说敌人一定开火；含义是旧版会丢弃较少损失的候选。原始输出与对照输入在evidence。

## 5.0报告中需要修正的推论

1. “防御价值符号反了”并不由那两行代码成立。防御后存活记0、仍死亡记负成本，可以与其他动作增量作比较。确认的问题是攻击候选被强制要求为正值。
2. 不能从资源分封顶的凹性推出“唯一正确目标是P(R≥120)”。稳定取得119资源约得29.75资源分，而一半概率拿120、一半拿0，封顶概率更高，期望资源分只有15。任务还含离散完成门槛，整个目标函数不能一概称为凹函数。应比较逐场实际总分，结合风险偏好。
3. 同版本对称性通过只能说明没有该类席位偏置，不能证明模拟器完全符合规则；缺回执、阵亡视野等问题仍需要单独检查。
4. 相同源码、随机种子、动作时序的确定性比分应可复现。耗时会抖动，不能把确定性比分的变化直接归于“随机噪声”。

## 验证范围

这些改动没有把推断当成实时真值：敌人离开视野后的坐标仅是带期限的历史假设；其分数、隐藏地图、未来动作和未公开增益均不可读取。事件仍由真实接入时的LLM解释，不以文本关键词替代。6.0的收益是否适用于官方事件局、真实网络及不同对手仍未知。
