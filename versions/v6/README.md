## 在克隆的仓库中运行

需要Ubuntu 22.04、ROS 2 Humble、C++17、colcon和libcurl开发依赖。下列命令基于仓库放在`~/ZKXWN`：

```bash
cd ~/ZKXWN/versions/v6
bash ./scripts/test.sh
bash ./scripts/build.sh
bash ./scripts/run.sh A 2
```

`cd`进入本版的程序目录；`bash`执行对应Shell脚本。`test.sh`是检查，`build.sh`是构建，`run.sh A 2`启动A席位第二阶段；第一个参数可改席位，第二个参数`1/2`代表阶段。裁判需要另行启动，公开ROS域及网关按现场要求配置，不能据启动成功认定获得真实AI资格。

切换版本前先停止旧节点，避免同一席位多个程序同时发动作。真实令牌只放运行环境，不提交仓库。

在仓库布局中，旧版对照路径应显式传入：

```bash
V4_ROOT="../v4" V5_ROOT="../v5" bash ./scripts/bench.sh --a 6 --b 4 --matches 100 --seed 83000 --robots 4
```

# 校内6.0

| 四人局，另两队为合法贪心，6对5 | 38.20 | 37.02 | +1.19 | 51.4% |

“胜率”指6.0得分严格超过指定对手的比例，平局不计胜；四人局不是整场冠军率。完整方法、全部结果和不确定性见[对抗验证报告.md](对抗验证报告.md)。

## Ubuntu本地核心检查

把整个`校内6.0`复制到Ubuntu主目录，打开终端执行：

```bash
cd ~/校内6.0
chmod +x scripts/*.sh
./scripts/test.sh
```

第一行进入文件夹；第二行为Shell脚本添加执行权限；第三行用CMake编译并运行核心、模拟LLM线程和规则检查。核心检查不需要ROS。源码附带JSON依赖，无需另找JSON头文件。

## 启动ROS节点

```bash
./scripts/build.sh
export ROS_DOMAIN_ID=27
./scripts/run.sh A 2
```

依次编译ROS节点、选择当前练习公开域、以A席位启动第二阶段。需要Ubuntu 22.04、ROS 2 Humble、colcon和curl开发库。裁判需另外启动，正式域以主办方要求为准。切换版本前先停止旧参赛节点，避免同一席位有多个程序发动作。

本版命名空间为`rmtc6`，ROS包和可执行文件为`rmtc_bot6`，包版本为`6.0.0`；启动脚本已同步改名。现场档位文件仍只含`decision_type`，支持`balanced/collect/fight`。

## 重做对抗测试

把`校内4.0`、`校内5.0`、`校内6.0`放在同一目录：

```bash
./scripts/bench.sh --a 6 --b 4 --matches 100 --seed 83000 --robots 4
./scripts/bench.sh --a 6 --b 5 --matches 100 --seed 83000 --robots 4
```

脚本编译原版4.0、5.0源码作为对手，默认跑四席位全部12种有序两两安排。可用`V4_ROOT`、`V5_ROOT`指定旧版文件夹。完整13组矩阵可在编译后用：

```bash
python3 tools/evaluate.py --arena build_arena/rmtc_arena --out evidence/rerun_01
```

输出目录必须是新目录，避免覆盖原始证据。该脚本只用Python标准库。

## 已验证与待验证

Windows MSVC19.51的Release、Debug各通过3992项断言，四组测试零失败。数量含循环性质断言，不是3992场比赛。最终第二阶段对比5120局、对称性432局，另有200组第一阶段独立地图对；所有这些测试中的各策略非法动作计数均为0。另做25,200次加速自对弈决策和JSONL缓存/换场次回放。
