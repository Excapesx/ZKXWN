# 6.0 检查报告

检查日期：2026-10-24。输入为桌面 HERO 中的 `校内6.0` 与官方 v1.1 材料、`03_官方练习包_v1.1`。7.0 另存，6.0 原文件夹保持原样。

## 结论

6.0 的决策核心在“无事件、对称、资源总量固定”的四人基准里已经接近公平份额上限，单靠调参无法再稳定多拿 5–10 分。它真正的问题是**规则边界和异常输入**：若干处会把“可以继续打”变成“整帧丢弃”“发一个必被拒绝的动作”或“任务分资格记账错误”。7.0 保留 6.0 的采集/越野/战斗主干，集中修这些边界。无事件基准因此与 6.0 同分（38.63 对 38.63，1200 局），这是预期结果，不是 7.0 没改到点子上。

## 没有改、也不应该假装改的

1. **堡垒驻留是否要求“移动后”**：规则 PDF §8.5 写“移动后位于堡垒内”，练习包 `stage2.json` 写“连续停留”。两者冲突。6.0/7.0 都按练习包的“在区域内累计”实现；正式场以裁判公告为准。7.0 没有把这一点包装成“修好了”。
2. **无事件基准的得分上限**：16 个资源总值 200，四家分。6.0 已经接近公平份额；7.0 没有、也不应该承诺在对称基准里 +10 分。要拉开差距只能靠对手失误、事件局决策或规则边界，而不是把同一份资源算两遍。
3. **`incoming_damage` 的上界假设**：6.0 把视野内所有能打到自己的敌车都按会开火估计。它是保守上界，不是预测；7.0 保留，避免为了“更聪明”而在真实对局里被集火打死。
4. **真实 ROS/curl/模型网关/官方事件整场**：本轮没有 Ubuntu 构建、没有真实网关、没有官方裁判回执。单元测试通过不等于现场通过。
