# 校内7.0

保存日期：2026-10-24。官方规则仍为 v1.1，7.0 是程序版本。

7.0 的重点不是把无事件基准的分母再抠 0.1 分，而是拆掉 6.0 在真实比赛里会**整场归零或白丢分**的失败模式：单条坏实体导致整帧拒收、世界分裂复活 Tick 发 MOVE、AI 资格只认非空正文、模型返回 `{}` 被当成解析失败、只挡 3 Tick 的临时墙、入点回血重复刷新等。无事件、对称、资源总量固定的四人基准里，7.0 与 6.0 同分；事件局和异常局的决策正确性才是 7.0 的“秒杀点”。逐条对照见[6.0检查报告.md](6.0检查报告.md)。

| --- | ---: | ---: | ---: | ---: | ---: |
| 四人局，1×7.0 对 3×6.0，100 图 1200 局 | 38.63 | 38.63 | 0.00 | 47.8%（平 4.3%） | 0 |
| 四人局，7.0 与 6.0 各一席 + 两席贪心，100 图 | 38.55 | 38.55 | 0.00 | 48.3% | 0 |

| 32×16、视野 2，1×7.0 对 3×6.0，60 图 | 38.31 | 38.31 | 0.00 | 47.4% | 0 |
| 7.0 对 7.0 对称性，50 图 600 局 | 39.42 | 39.42 | 0.00 | 46.8% | 0 |
| 第一阶段 20×20，100 图独立地图 | 38.02 | 38.02 | 0.00 | 平 100 局 | 0 |

“胜率”指 7.0 得分严格超过指定 6.0 的比例，平局不计胜；1×7 对 3×6 的每一局会与三个 6.0 各比一次，所以胜/平/负之和是 1200。无事件基准中双方资源总量固定为 200，四家公平分配，6.0 已经接近这个基准的上限；任何“+10 分”的承诺都只能来自抢走对手份额或对手失误，不能来自调参。完整方法、全部结果和不能外推的部分见[对抗验证报告.md](对抗验证报告.md)。

## 为什么不是 6.0 换个名字

7.0 保留 6.0 已验证的采集、定向越野、战斗估值和现场档位，只改了三类东西：

1. **不再整帧丢弃**：单条坏实体只跳过该实体；缺 `visible_entities` 仍可决策但不清地图记忆；`team` 写成长期 ID 也能接受；坏实体不再让整场变成 WAIT。
2. **事件与时序正确**：世界分裂复活 Tick 强制 WAIT；时间展开 BFS 按“到达该格的 Tick”判断临时墙；入点回血只认“从点外进入”；强化天使、堡垒、辣椒的战术目标。
3. **AI 资格与降级**：HTTP 2xx 即记本场资格；空对象 `{}` 是合法“无事件计划”；5 Tick 重试、最多 20 次；同时订阅 `/referee/event_text` 和 `/referee/mission`，不把公告是否出现在感知里当作唯一来源。

## Ubuntu 本地核心检查

把整个 `校内7.0` 复制到 Ubuntu 主目录，打开终端执行：

```bash
cd ~/校内7.0
chmod +x scripts/*.sh
./scripts/test.sh
```

第一行进入文件夹；第二行为 Shell 脚本添加执行权限；第三行用 CMake 编译并运行五组本地检查。核心检查不需要 ROS。源码附带 JSON 依赖，无需另找 JSON 头文件。

## 启动 ROS 节点

```bash
./scripts/build.sh
export ROS_DOMAIN_ID=27
./scripts/run.sh A 2
```

依次编译 ROS 节点、选择当前练习公开域、以 A 席位启动第二阶段。需要 Ubuntu 22.04、ROS 2 Humble、colcon 和 curl 开发库。裁判需另外启动，正式域以主办方要求为准。切换版本前先停止旧参赛节点，避免同一席位有多个程序发动作。

本版命名空间为 `rmtc7`，ROS 包和可执行文件为 `rmtc_bot7`，包版本为 `7.0.0`；启动脚本已同步改名。现场档位文件仍只含 `decision_type`，支持 `balanced/collect/fight`。

## 重做对抗测试

把 `校内6.0`、`校内7.0` 放在同一目录：

```bash
./scripts/bench.sh --a 7 --b 6 --others 6 --matches 100 --seed 83000 --robots 4
```

脚本编译原版 6.0 源码作为对手，默认跑四席位全部 12 种有序两两安排。可用 `V6_ROOT` 指定 6.0 文件夹。完整 7 组矩阵可在编译后用：

```bash
python3 tools/evaluate.py --arena build_arena/rmtc_arena --out evidence/rerun_01
```

输出目录必须是新目录，避免覆盖原始证据。该脚本只用 Python 标准库。

## 已验证与待验证

Windows MSVC 19.51 的 Release 构建通过。五组测试共 4016 项断言：141 旧核心、11 模拟 LLM 线程、613 既有边界、3228 情景/性质、23 新增 7.0 契约，零失败。第二阶段 7 对 6 共 4120 局（含 1×7 对 3×6、2v2、矩形图、对称性），第一阶段 100 张独立地图，所有策略非法动作计数均为 0。本机决策 p99 约 0.07 ms、最大约 0.4 ms（不含 DDS、模型和 ROS 发布链路）。

本轮未在 Ubuntu 构建或运行 ROS、未编译真实 curl 传输、未连接模型网关，未完成官方第二阶段整场事件局。模拟器没有随机事件，任务分假设已具备 AI 资格；实际任务资格必须由本场真实成功调用取得。新增的时间展开 BFS、分裂 WAIT、入点回血、空计划、AI 资格逻辑已有单元测试，但不能代替现场验收。

本包是完整源码和资料，不包含构建缓存、真实凭据或编译后的参赛二进制。官方三份 PDF 和 dist.zip 保留原始字节；`文件清单.json` 用于完整性核对。
