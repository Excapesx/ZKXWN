# 程序逻辑与学习指南

## 一帧消息怎样变成动作

ROS节点收到本席位的JSON感知后，先检查字段、场次和Tick。同Tick重复消息重发缓存动作，不再重复推进策略。新场次清空地图、事件、追击记忆和旧模型请求的影响。终局消息不发动作。

决策引擎用当前感知更新地图，记录已见过的资源和障碍。未知区域保持未知。其他车在当前视野内的位置可以直接用；离开视野后，旧位置仅用作会逐渐失效的搜索假设。

若是第一阶段，就在剩余Tick预算内规划采集路线，输出移动或等待。第二阶段先检查已知前置事件：当前已经必死时等待；下一Tick会危险时尝试提前离开。这里要分清“现在已经中招”和“下一Tick将中招”。

随后产生资源、到点任务、探索、事件收益和追击候选。资源最多向前看两站，给可能被抢走的第二站打折，不假定整条长期路线都归自己。任务按ID逐项检查。资源剥夺与信息收益是策略偏好，不是裁判已经给的分。

能打到人时，分别估计敌人暂不进攻、集中攻击自己和寻找攻击机会三种情景。每辆敌人只能选一个动作。把实际贡献、击杀分摊和死亡扣除按同一批次算完，再比较攻击、防御及目标移动。对手下一步并不知道，三种情景也没有覆盖全部可能性。

最后由出口守卫再次检查：阵亡等待、保护期不攻击、第一阶段只移动或等待、方向必须合法。ROS节点把动作连同原始Tick和session_id发出，并保存本Tick缓存。

## LLM在这里做什么

随机事件公告交给异步LLM线程解释成经过校验的结构化事件。决策主循环可以继续运行，不等网络返回。迟到的旧场次结果会丢弃，计划会检查时间、位置和类型。没有真实模型API时可以做核心练习，但不能把模拟成功当作正式比赛任务资格。

## 从哪些文件读起

| 文件 | 先理解的问题 |
| --- | --- |
| src/rmtc6/types.hpp | 一帧感知里允许知道哪些东西？动作如何表示？ |
| src/rmtc6/bot.cpp | 同一Tick有哪些候选，为什么选这个？ |
| src/rmtc6/battle.cpp | 一人一个动作时，伤害怎样同时结算？ |
| src/rmtc6/grid.cpp | 未知、空地和障碍的区别；BFS怎样给出第一步？ |
| src/rmtc6/events.cpp | 事件什么时候开始、到期，哪些效果跨死亡保留？ |
| ros2_ws/src/rmtc_bot6/src/node.cpp | 感知话题、缓存、场次切换和动作发布怎样接起来？ |

## 命令拆解

`cd ~/校内6.0`：`cd`是切换目录，`~`是当前用户主目录，后面是要进入的文件夹。进入目录不会启动程序。

`chmod +x scripts/*.sh`：`chmod`修改文件权限，`+x`添加可执行权限，`scripts/*.sh`匹配scripts文件夹中所有以.sh结尾的脚本。它不会安装ROS。

`./scripts/test.sh`：开头`./`表示从当前目录找文件。脚本调用CMake构建，再用CTest执行四组本地检查。通过只说明这些用例通过，不能说明已连通裁判。

`./scripts/build.sh`：加载Humble环境，用colcon编译rmtc_bot6。需要在Ubuntu安装相应依赖，Windows的核心编译通过不代替这一步。

`export ROS_DOMAIN_ID=27`：为当前终端及它启动的进程设置ROS通信域。27用于目前的公开练习。它不会启动裁判，也不会自动修改其他终端。

`./scripts/run.sh A 2`：启动A席位的第二阶段节点；A和2是传给脚本的两个参数。其他席位换成B、C、D，第一阶段把2换成1。

`./scripts/bench.sh --a 6 --b 5 --matches 100 --seed 83000 --robots 4`：离线比较6.0和5.0，生成100张确定种子地图、四人局全席位轮换。它不连接ROS，不访问模型，也不是官方比赛。

## 一次只学一个目标

先找一条回放输出，按“感知中的自己位置和HP → 看得见的目标 → 候选动作 → 最终reason”说明程序为什么这样走。再手动改一份测试夹具的敌人HP，运行回放，比较是否改选攻击。夹具只是学习材料，不能写进正式参赛代码当作已知地图。
